============================================================
[03:00 – 10:00] ما هو إطار العمل ولماذا Flask
============================================================

قبل كتابة أي كود، دعونا نفهم ماذا يعني "إطار عمل".

إطار العمل (Framework) هو مجموعة أدوات وقواعد جاهزة
تختصر بناء الجزء المتكرر من التطبيق. في أي تطبيق ويب،
هناك أشياء تتكرر في كل مشروع:
- استقبال طلب HTTP من المتصفح.
- تحليل الطلب (الطريقة، المسار، الترويسات، البيانات).
- توجيهه إلى الكود المناسب.
- تجهيز الاستجابة (نص، HTML، JSON، ملف).
- التعامل مع الأخطاء (404، 500…).

بدون إطار عمل، ستكتب هذه الحلقة بنفسك من الصفر.
ستستخدم socket، وparse HTTP يدوياً، وتربط المسارات،
وتُدير الأخطاء. هذا تعليمي مرة واحدة، لكنه مضيعة وقت
في كل مشروع.

مع إطار العمل، تبدأ من حيث يجب: من منطق تطبيقك.

أطر العمل الشائعة في Python:
- Flask: خفيف، مرن، صغير، سهل التعلم.
- Django: كامل، يوفّر ORM، admin، auth.
- FastAPI: حديث، سريع، قائم على type hints.

اخترنا Flask لهذا المساق. لماذا؟
لأنه يسمح لنا بالتركيز على المفاهيم لا على تعقيد
الإطار. كل شيء في Flask واضح: دالة Python، مسار،
وما ترجعه الدالة هو ما يراه المستخدم. حين تفهم هذا،
يمكنك الانتقال لاحقاً إلى Django أو FastAPI بنفس
المبادئ.

تخيلوا العلاقة:
المتصفح يرسل طلب GET /about.
Flask يستقبله، ويبحث في جدول المسارات: "هل يوجد مسار
/about؟". يجد الدالة def about(). ينفذها. الدالة ترجع
نص "عن المساق". Flask يغلّفه في استجابة HTTP ويرسله.
المتصفح يعرض النص.

هذه هي الفكرة بأكملها. الباقي تفاصيل.

============================================================
[25:00 – 40:00] أول تطبيق
============================================================

الآن نكتب أول تطبيق. اسم الملف app.py (أو main.py،
لكن app.py هو الأكثر شيوعاً).

الكود كامل:

from flask import Flask

app = Flask(__name__)


@app.route("/")
def home():
    return "مرحباً بك في أول تطبيق Flask!"


if __name__ == "__main__":
    app.run(debug=True)

دعونا نشرح كل جزء.

أولاً: from flask import Flask.
نستورد الفئة Flask من مكتبة Flask. الكلمة الأخيرة
وقبلها upper، لا تخلطوا بين flask (المكتبة) وFlask
(الفئة).

ثانياً: app = Flask(__name__).
ننشئ كائن التطبيق. __name__ يخبر Flask باسم الحزمة
الحالية، ويعتمد عليه للعثور على القوالب والملفات.
لا تغيّروا هذا المعامل الآن.

ثالثاً: @app.route("/").
هذا يسمى decorator (مزخرف). وظيفته: "عندما يطلب
المستخدم المسار /، نفّذ هذه الدالة". المزخرف يعدّل
دالة home، فيصبح Flask يعرفها كمعالج لهذا المسار.

رابعاً: def home(): return "...".
الدالة نفسها لا شيء فيها سوى return. لكن ما ترجعه
هو ما يراه المتصفح. الآن هو نص، لاحقاً HTML أو قالب.

خامساً: app.run(debug=True).
يشغّل الخادم المحلي على المنفذ 5000 افتراضياً.
debug=True يعطي ميزتين:
1) إعادة تشغيل تلقائية عند تعديل الملفات.
2) صفحة أخطاء تفصيلية عند حدوث استثناء.

نشغّل التطبيق بأحد أمرين:

python app.py

أو:

set FLASK_APP=app.py    (Windows)
export FLASK_APP=app.py (macOS/Linux)
flask run

بعد التشغيل، افتحوا http://127.0.0.1:5000.
سترون النص الذي كتبناه. مبروك — أول تطبيق ويب حقيقي
لكم يعمل على خادم.

ملاحظة على 127.0.0.1: هو عنوان "هذا الجهاز" (localhost).
لا يمكن لأحد على الشبكة الوصول إلى تطبيقكم. لو أردتم
العرض على الشبكة المحلية، استخدموا host="0.0.0.0" بحذر،
لأن ذلك يفتح المنفذ لكل من على الشبكة.

نصيحة: في هذه المرحلة، افتحوا الطرفية والمتصفح جنباً إلى
جنب. عدّلوا النص، احفظوا، وشاهدوا Flask يعيد التشغيل
ويعرض النص الجديد. هذه التجربة الأولى تفيدكم أكثر من
عشر شرائح نظرية.

[40:00 – 55:00] المسارات المتعددة
============================================================

تطبيق بمسار واحد لا يكفي. لنضف مسارات.

from flask import Flask

app = Flask(__name__)


@app.route("/")
def home():
    return "الصفحة الرئيسية"


@app.route("/about")
def about():
    return "عن المساق: SYBS 2309"


@app.route("/contact")
def contact():
    return "البريد: makhalil@ucas.edu.ps"


@app.route("/courses/web")
def web():
    return "صفحة مقرر الويب"


if __name__ == "__main__":
    app.run(debug=True)

كل @app.route يضيف مساراً. كل دالة مستقلة. عند زيارة
/courses/web، ينفذ Flask الدالة web. وعند زيارة /،
ينفذ home. وهكذا.

ملاحظات مهمة:

أولاً: المسار يبدأ دائماً بـ /. @app.route("about")
خطأ. الصواب "/about". ونفس الشيء على الجذر: "/" وليس
"". هذا يسبب ValueError عند بدء التشغيل.

ثانياً: المسار المتداخل /courses/web مسموح. Flask
يبحث عن المطابقة الأطول. إذا كان لدينا /courses
و/courses/web، فكل يذهب لدالته.

ثالثاً: يمكن تكرار @app.route على دالة واحدة، لتعريف
مسارات متعددة، مثل:

@app.route("/home")
@app.route("/index")
def home():
    return "..."

هذه نمط شائع لتوافق عناوين قديمة.

رابعاً: ماذا لو طلب المستخدم مساراً غير موجود؟
Flask يعيد صفحة 404 Not Found تلقائياً. هذه ليست
مشكلة، بل نتيجة طبيعية. لاحقاً سنتعلم كيف نعرض 404
مخصصة.

============================================================
[55:00 – 70:00] المعاملات الديناميكية
============================================================

المسارات الثابتة لا تكفي. نحتاج أحياناً أن نمرر أجزاءً
من العنوان. مثلاً /hello/sara، /hello/ahmed، كلاهما
يشترك في نفس الشكل.

Flask يدعم ذلك بـ<>:

@app.route("/hello/&lt;name&gt;")
def hello(name):
    return f"مرحباً {name}!"

النص بين < > يصبح معاملاً في الدالة. اسم المعامل في
الدالة يجب أن يطابق الاسم بين <>.

جرّبوا:
/hello/sara → "مرحباً sara!"
/hello/ahmed → "مرحباً ahmed!"

النوع الافتراضي هو نص. لكن يمكننا تقييده:

@app.route("/student/&lt;int:sid&gt;")
def student(sid):
    return f"رقم الطالب: {sid}"

الآن /student/42 يعمل. لكن /student/abc لا يطابق،
فيرجع 404. هذا مفيد لأنه يقلل التحقق اليدوي.

أنواع مدعومة:
- string (افتراضي): لا يقبل /
- int: أعداد صحيحة
- float: أعداد عشرية
- path: يقبل /
- uuid: معرّفات UUID

مثال على /path/:
@app.route("/files/&lt;path:filepath&gt;")
def files(filepath):
    return f"الملف: {filepath}"

هذا يطابق /files/docs/notes.txt.

تنبيه أمني مهم: ما يأتي في URL من المستخدم، وليس
موثوقاً. حتى مع <int:sid>، تحققوا أن المعرّف موجود
فعلاً، وأن المستخدم له صلاحية الوصول. لا تعتمدوا على
القيد النوعي وحده للأمان.

هذا المبدأ سيتردد أكثر في Flask، لأن كل ما يأتي من
الـ request من المستخدم: بيانات النموذج، الترويسات،
الكوكيز، الملفات. كل هذه تحتاج تحققاً في الخادم.

[70:00 – 85:00] طرق HTTP
============================================================

كل طلب HTTP له طريقة. الافتراضي في Flask هو GET.
عندما تكتب @app.route("/about")، تعني فعلياً
methods=["GET"]. هذا مناسب للقراءة.

لو أردنا قبول POST أيضاً:

@app.route("/subscribe", methods=["GET", "POST"])
def subscribe():
    if request.method == "POST":
        email = request.form.get("email", "")
        return f"تم استلام: {email}"
    return "أرسل بريدك عبر POST."

request.method يخبرنا بالطريقة الحالية. request.form
قاعدة بيانات النموذج (لـPOST). request.args لـGET.
سنتعلم النماذج في المحاضرة القادمة، لكن الآن افهموا
الفرق:

GET:
- البيانات في URL.
- مناسبة للبحث والتصفح.
- تظهر في السجل والـhistory.

POST:
- البيانات في جسم الطلب.
- مناسبة للتسجيل والدخول والتحديث.
- لا تظهر عادة.

قاعدة أمنية: لا ترسلوا كلمات المرور أو الرموز الحساسة
بـGET. استخدموا POST مع HTTPS. حتى مع POST، لا تكفي
HTTPS وحدها للامتلاء — التحقق في الخادم ضروري.

سيناريو شائع: نموذج تسجيل.
- صفحة GET /register: تعرض النموذج.
- نموذج يرسل POST /register: يستقبل البيانات، يتحقق،
  يحفظ، ثم يوجه أو يعيد صفحة نجاح.

هذا النمط يسمى Post/Redirect/Get. سنراه لاحقاً. الآن
يكفي أن تفهموا أن نفس المسار يمكن أن يخدم طريقتين
حسب الحالة.

============================================================
[85:00 – 100:00] الاستجابات والقوالب
============================================================

ناتج الدالة هو ما يراه المتصفح. الآن هو نص فقط. لكن
تطبيقاً حقيقياً يحتاج HTML.

خياران:

الأول: HTML مضمّن في الدالة.
@app.route("/html")
def html_demo():
    return """
    <!DOCTYPE html>
    <html lang="ar" dir="rtl">
    <head><meta charset="UTF-8"><title>...</title></head>
    <body><h1>مرحباً من Flask</h1></body>
    </html>
    """

هذا يعمل، لكنه سيئ. لماذا؟
- يخلط HTML مع Python.
- يصعب تحريره (لا syntax highlighting جيد).
- يكرر القالب في كل مسار.
- صيانة صعبة.

الثاني (الأفضل): render_template + Jinja.

نضع الملفات في مجلد templates/.

app.py:
from flask import Flask, render_template

@app.route("/template")
def template_demo():
    return render_template(
        "home.html",
        title="مرحباً من القالب",
        name="سارة"
    )

templates/home.html:
<!DOCTYPE html>
<html lang="ar" dir="rtl">
<head><title>{{ title }}</title></head>
<body>
  <h1>{{ title }}</h1>
  <p>مرحباً {{ name }}، هذا قالب من Jinja2.</p>
</body>
</html>

{{ title }} و{{ name }} هي تعبيرات Jinja. Flask
يستبدلها بالقيم قبل إرسال HTML.

فوائد هذا:
- HTML نظيف في ملفه.
- يمكن إعادة استخدام قاعدة مشتركة.
- يمكن تشغيل tooling HTML على القوالب.
- لا نكتب HTML داخل Python.

ملاحظة على الأمان: Jinja يهرّب تلقائياً القيم التي
تُمرَّر إليه. لكن هذا لا يحل مشكلة الثقة بالمستخدم.
لا تستخدموا |safe على مدخلات المستخدم أبداً. |safe
تعني "لا تهرّب"، وهذا يفتح XSS. استخدموها فقط مع HTML
تكتبونه أنتم أو مصفّى بحذر.

في المحاضرة القادمة سنتوسع في القوالب: الوراثة
({% extends %})، الكتل ({% block %})، الحلقات
({% for %})، والشروط ({% if %}). اليوم نكتفي بالأساس.

[100:00 – 110:00] وضع التصحيح
============================================================

debug=True عند app.run() يفعّل ميزتين:

1) إعادة تحميل تلقائية.
عند تعديل الملفات، Flask يعيد التشغيل. هذا يوفّر
دورة إيقاف-تشغيل-انتظار، ويجعل التطوير أسرع.

2) صفحة أخطاء تفصيلية.
عند حدوث استثناء، يعرض Flask صفحة HTML جميلة فيها:
- نوع الاستثناء.
- رسالة الخطأ.
- Traceback كامل.
- السطر الذي فشل.
- أحياناً Console تفاعلي لفحص المتغيرات.

جرّبوا:
@app.route("/boom")
def boom():
    return 10 / 0

ثم افتحوا /boom. سترون صفحة خطأ تفصيلية.

هذه الصفحة صديقتكم في التطوير. اقرؤوها بعناية. غالباً
ستجدون السطر الذي يسبب الخطأ والسبب مباشرة.

لكن — وهذا تحذير جدي — لا تتركوها في الإنتاج.

لماذا؟
- تعرض شيفرتكم ومسار الملفات.
- تعرض متغيرات قد تحتوي بيانات حساسة.
- قد تفتح Console تفاعلياً يسمح بتشغيل كود.
- تخبر المخترق عن بنية التطبيق.

القاعدة: debug=True في التطوير، false في الإنتاج،
مع خادم إنتاج (gunicorn, uWSGI, Waitress) وليس
app.run().

<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">

مسار جذري. سنتوسع فيه لاحقاً.

[135:00 – 145:00] أخطاء شائعة
============================================================

دعونا نمرّ على الأخطاء:

أولاً: نسيان / في المسار.
@app.route("about") خطأ.
الصواب /about.

ثانياً: تشغيل التطبيق من مجلد خاطئ.
flask run يحتاج app.py في نفس المجلد، أو تحديده بـ
--app. إذا لم يجده: "Could not locate an app".

ثالثاً: اسم معامل لا يطابق.
/app/&lt;name&gt; يجب أن تقابله def app(name)، لا def app(n).

رابعاً: ترك debug=True في الإنتاج.
يكشف تفاصيل التطبيق. عطّلوه دائماً.

خامساً: نسيان templates/.
render_template("home.html") يبحث في templates/.
إن كتبتم الملف في الجذر، TemplateNotFound.

سادساً: المنفذ 5000 مشغول.
رسالة "Address already in use". أغلقوا النسخة القديمة
أو استخدموا port=5001.

سابعاً: عدم تفعيل البيئة (venv).
"Flask غير مثبت" رغم تثبيته. افتحوا طرفية جديدة أو
أعدوا التفعيل.

ثامناً: ظن أن 127.0.0.1 يعرض على الشبكة.
هو "هذا الجهاز" فقط. للشبكة المحلية host="0.0.0.0"
بحذر.

تاسعاً: استخدام |safe مع بيانات المستخدم.
يفتح XSS. لا تفعلوا.

عاشراً: وضع منطق طويل داخل @app.route.
الدالة يجب أن تستدعي دوالاً مساعدة، لا أن تحتوي كل
شيء. الفصل يسهل الاختبار.

نصائح:
- ابدأوا بأبسط تطبيق، ثم أضيفوا.
- اسم الملف app.py، واسم متغير التطبيق app.
- اقرؤوا رسائل الخطأ في الطرفية.
- استخدموا debug=True أثناء التطوير فقط.
- رتّبوا المسارات بحسب الشكل.
