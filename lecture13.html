Jinja2: تعابير وكتل

Jinja2 هو مُحرّك القوالب الذي يأتي مع Flask. يحوّل ملفات HTML التي تحتوي على صياغة خاصة إلى HTML نهائي قبل إرسالها للمتصفح. الصياغة نوعان:

{{ }} — تعابير

  • تُستخدم لطباعة قيمة
  • مثل متغير أو تعبير حسابي
  • مثال: {{ name }}
  • يمكن استدعاء دوال داخلها

{% %} — كتل تحكم

  • للتحكم في التدفق والعرض
  • if، for، block، extends
  • لا تُطبع قيمتها
  • تتحكم في بنية القالب

{# #} — تعليقات

  • تعليقات لا تظهر في HTML
  • مفيدة لتوثيق القوالب
  • لا تُرسل للمتصفح
  • لا تُنفّذ

الهروب التلقائي

  • Jinja يهرّب HTML افتراضياً
  • يمنع XSS من القيم
  • |safe يعطّل الهروب
  • استخدمها فقط مع HTML موثوق
templates/hello.html HTML + JINJA 
<!DOCTYPE html>
<html lang="ar" dir="rtl">
<head>
    <meta charset="UTF-8">
    <title>{{ title }}</title>
</head>
<body>
    {# عنوان الصفحة #}
    <h1>{{ title }}</h1>

    <p>مرحباً {{ name }}، عمرك {{ age }} سنة.</p>

    {# شرط #}
    {% if age >= 18 %}
        <p>أنت بالغ.</p>
    {% else %}
        <p>أنت قاصر.</p>
    {% endif %}

    {# حلقة #}
    <ul>
    {% for skill in skills %}
        <li>{{ skill }}</li>
    {% else %}
        <li>لا توجد مهارات.</li>
    {% endfor %}
    </ul>
</body>
</html>
app.py — استدعاء القالب PYTHON 
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/hello")
def hello():
    return render_template(
        "hello.html",
        title="صفحة ترحيب",
        name="سارة",
        age=20,
        skills=["HTML", "CSS", "Python"]
    )
فوائد القوالب: HTML صار في ملفه، ومنطق Python في ملفه. لا مزيد من return "<h1>...</h1>" داخل الدالة. الكود يُقرأ ويُصان بسهولة، ويمكن لمصمم HTML أن يعمل على القالب دون لمس Python.
قيم افتراضية ومرشحات:
• {{ name | default('زائر') }} يعطي قيمة افتراضية.
• {{ price | round(2) }} يقرّب لخانتين.
• {{ text | upper }} يحوّل للأحرف الكبيرة.
• {{ items | length }} يعيد عدد العناصر.

تمرير البيانات من Python إلى القالب

دالة render_template() تقبل اسم القالب أولاً، ثم سلسلة من المعاملات المسماة (keyword arguments). كل معامل يُصبح متغيراً متاحاً داخل القالب. وهذه هي الطريقة التي تعرض بها بياناتك.

app.py — تمرير بيانات متعددة PYTHON 
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/courses")
def courses():
    # بيانات من أي مصدر: قاعدة بيانات، ملف، API...
    courses_list = [
        {"code": "SYBS 2309", "title": "تصميم وبرمجة الويب", "active": True},
        {"code": "SYBS 1010", "title": "مقدمة إلى الأمن", "active": False},
        {"code": "SYBS 2020", "title": "شبكات الحاسوب", "active": True},
    ]

    return render_template(
        "courses.html",
        title="قائمة المقررات",
        courses=courses_list,
        total=len(courses_list)
    )
templates/courses.html HTML + JINJA 
<h1>{{ title }}</h1>
<p>عدد المقررات: {{ total }}</p>

<table>

        <tr>
            <th>الرمز</th>

        <tr>

            {% if c.active %}
                نشط
            {% else %}

    </tbody>
</table>

أنواع البيانات

  • يمكن تمرير أي نوع Python
  • نص، رقم، قائمة، قاموس
  • دالة، كائن، خصائص
  • Jinja يصل إليها مباشرة

الوصول للخصائص

  • d.key أو d["key"]
  • Jinja جرّبت الاثنين
  • لو لم يوجد المفتاح → undefined
  • لا يرفع KeyError

تعابير

  • عمليات حسابية: {{ a + b }}
  • مقارنات منطقية داخل {% if %}
  • سلاسل: {{ 'x' ~ name }}
  • مرشحات: {{ price | round(2) }}

undefined

  • قيمة غير مزوّدة → undefined فارغ
  • لا خطأ، لكن النتيجة فارغة
  • تحقق في التطوير قبل النشر
  • استخدم | default عند الحاجة
لا تعتمد على ترتيب المعاملات! render_template("x.html", name, email) خطأ. يجب استخدام المعاملات المسماة: name=name, email=email. الترتيب بلا أسماء يُنتج استدعاءً غير معروف للدالة.

وراثة القوالب وبنية المشروع

تخيل أن لديك 10 صفحات، كل واحدة تحتاج نفس <head> ونفس <header> و<footer>. تكرارها في كل ملف كارثة صيانة. وراثة القوالب تحل هذا نهائياً: نكتب base.html مرة واحدة، ثم كل صفحة ترث منه وتضيف محتواها.

base.html

  • القالب الأب
  • يحتوي الترتيب العام
  • يُعرّف {% block %}
  • لا يُعرض مباشرة عادة

extends

  • السطر الأول في القالب الابن
  • {% extends "base.html" %}
  • يجب أن يكون أول شيء
  • يكتب مرة واحدة فقط

block

  • مكان قابل للاستبدال
  • يعرَّف في الأب ويُملأ في الابن
  • مثال: {% block content %}
  • يمكن استدعاء محتوى الأب بـ{{ super() }}

    <title>{% block title %}SYBS 2309{% endblock %}</title>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">
</head>
<body>
    <header class="site-header">
        <h1>SYBS 2309</h1>
        <nav>
            <a href="{{ url_for('home') }}">الرئيسية</a>

            <a href="{{ url_for('contact') }}">تواصل</a>
        </nav>
    </header>

    <main>
        {# رسائل Flash (سنشرحها لاحقاً) #}
        {% with messages = get_flashed_messages(with_categories=true) %}
            {% if messages %}
                <ul class="flash-list">
                {% for category, msg in messages %}
                    <li class="flash flash-{{ category }}">{{ msg }}</li>
                {% endfor %}
                </ul>
            {% endif %}
        {% endwith %}

        {% block content %}{% endblock %}
    </main>

    <footer class="site-footer">
        <p>© 2025 Cyber Khalil — جميع الحقوق محفوظة</p>
    </footer>

    <script src="{{ url_for('static', filename='js/main.js') }}" defer></script>
</body>
</html>

{% block title %}الرئيسية — SYBS 2309{% endblock %}

{% block content %}
    <h2>مرحباً بكم في مساق تصميم وبرمجة الويب</h2>

النتيجة: كل صفحة جديدة = 10–15 سطراً فقط. الترويسة والتذييل وروابط CSS/JS تُكتب مرة واحدة في base.html. لو أردت إضافة رابط جديد في التنقل، تُعدّل سطراً واحداً فيتغير في كل الصفحات. هذا هو مبدأ DRY — Don't Repeat Yourself.
تحذير: {% extends %} يجب أن يكون أول وسم في الملف. أي مسافة بيضاء أو تعليق قبله يسبب خطأ TemplateSyntaxError. لا <!DOCTYPE> في ملفات الأبناء — هي في base.html فقط.

static وurl_for

الملفات الثابتة — CSS، JavaScript، الصور، الخطوط — تُوضع في مجلد static/. Flask يخدمها مباشرة للمتصفح دون المرور عبر render_template. الأمر الأهم: لا تكتب مساراتها يدوياً، استخدم url_for.

static/

  • مجلد افتراضي في Flask
  • CSS · JS · صور · خطوط
  • تُقدَّم مباشرة للمتصفح
  • لا تمر بـPython

url_for

  • يولّد المسار تلقائياً
  • للملفات الثابتة وللمسارات
  • يعمل مهما كان اسم الملف
  • يفضّل على الكتابة اليدوية

url_for لمسار

  • url_for('home')
  • يعيد المسار من اسم الدالة
  • يمكن تمرير معاملات URL
  • url_for('student', sid=42)

لا تكتب يدوياً

  • href="/static/css/style.css" قد ينكسر
  • إذا نُشر التطبيق على subpath
  • أو تغيّر اسم المجلد
  • url_for يحلّها دائماً
استخدام url_for في القوالب HTML + JINJA 
{# ربط ملف CSS #}
<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">

{# ربط ملف JavaScript #}
<script src="{{ url_for('static', filename='js/main.js') }}" defer></script>

{# صورة #}
<img src="{{ url_for('static', filename='images/logo.png') }}"
     alt="شعار المساق">

{# رابط لمسار داخلي #}
<a href="{{ url_for('home') }}">الرئيسية</a>

{# رابط لمسار بمعامل #}
<a href="{{ url_for('student', sid=42) }}">ملف الطالب 42</a>
app.py — ربط الأسماء بالدوال PYTHON 
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/")
def home():
    return render_template("home.html")


@app.route("/student/<int:sid>")
def student(sid):
    return render_template("student.html", sid=sid)
اسم الدالة هو اسم المسار: url_for('home') يشير إلى الدالة المسماة home، لا إلى /. لو غيّرت @app.route("/home") إلى @app.route("/start")، ستبقى url_for('home') تعمل، وستولّد /start تلقائياً. هذه ميزة كبيرة عند التطور.

GET وPOST في النماذج

النموذج في HTML يرسل بيانات إلى مسار. اختيار method (GET أو POST) يحدد أين تُرسل البيانات وكيف يقرأها الخادم.

المحور GET POST
مكان البيانات في URL (query string) في جسم الطلب (body)
قراءتها في Flask request.args request.form
يظهر في السجل نعم لا عادة
للبيانات الحساسة ممنوع مع HTTPS
آمن للإعادة نعم (Idempotent) لا (يُنشئ/يعدّل)
الاستخدام الشائع بحث، تصفية، تصفح تسجيل، دخول، إرسال
مسار يستقبل GET وPOST PYTHON 
from flask import Flask, render_template, request

app = Flask(__name__)


@app.route("/contact", methods=["GET", "POST"])
def contact():
    if request.method == "POST":
        # بيانات النموذج من جسم الطلب
        name = request.form.get("name", "")
        email = request.form.get("email", "")
        return render_template(
            "result.html",
            name=name,
            email=email
        )

    # GET: نعرض النموذج
    return render_template("contact.html")
templates/contact.html HTML + JINJA 
{% extends "base.html" %}

{% block title %}تواصل معنا{% endblock %}

{% block content %}
    <h2>تواصل معنا</h2>

    <form action="{{ url_for('contact') }}" method="post">
        <p>
            <label for="name">الاسم</label>
            <input type="text" id="name" name="name" required>
        </p>

        <p>
            <label for="email">البريد الإلكتروني</label>
            <input type="email" id="email" name="email" required>
        </p>

        <button type="submit">إرسال</button>
    </form>
{% endblock %}
لا تنسَ methods=["POST"]: بدونها، المسار يقبل GET فقط، ويرجع Flask خطأ 405 Method Not Allowed عند إرسال POST. هذا من أشهر أخطاء المبتدئين.
نمط Post/Redirect/Get (PRG): إذا أراد المستخدم بعد POST تحديث الصفحة، فقد يُعاد إرسال البيانات. الحل الاحترافي: بعد معالجة POST، اعمل redirect(url_for('...')). بهذا لا يمكن للمستخدم إعادة الإرسال بتحديث الصفحة.

استقبال بيانات النموذج في Python

في Flask، نقرأ بيانات النموذج من كائن request. لكل طريقة مصدرها الخاص: request.form لـPOST، وrequest.args لـGET، وrequest.files للملفات.

request.form

  • بيانات POST
  • قاموس بأزواج name/value
  • .get('name') للقراءة الآمنة
  • نصوص دائماً

request.args

  • بيانات GET (query string)
  • ?q=python&page=2
  • .get('q') للقراءة
  • نصوص دائماً

request.files

  • ملفات مرفوعة
  • input type="file"
  • يحتاج enctype في النموذج
  • حذر أمني شديد

.get() مقابل []

  • request.form['name'] ← KeyError
  • request.form.get('name') ← None
  • الأفضل: .get('name', '')
  • قيمة افتراضية تتجنب أخطاء
قراءة الحقول بأمان PYTHON 
@app.route("/subscribe", methods=["GET", "POST"])
def subscribe():
    if request.method == "POST":
        # قراءة آمنة — قيمة افتراضية لو المفتاح مفقود
        email = request.form.get("email", "").strip()
        name = request.form.get("name", "").strip()
        topics = request.form.getlist("topics")   # checkboxes

        # تحقق بسيط
        errors = []
        if not email:
            errors.append("البريد مطلوب")
        if "@" not in email:
            errors.append("البريد غير صالح")

        if errors:
            return render_template(
                "subscribe.html",
                errors=errors,
                email=email,     # نُعيد القيمة للمستخدم
                name=name
            )

        # نجاح
        return render_template("thanks.html", name=name)

    return render_template("subscribe.html", errors=[], email="", name="")
عند الفشل، أعد القيم للمستخدم: لو أخطأ المستخدم في حقل واحد، لا تجعله يعيد كتابة كل شيء. أعد إليه القيم الصحيحة في النموذج: value="{{ name }}". هذه بادرة صغيرة لكنها تحسّن التجربة كثيراً.
لا تثق بأي قيمة: كل ما في request.form وrequest.args جاء من المستخدم. قد يكون فارغاً، طويلاً جداً، أو يحتوي وسوم HTML. لا تستخدمه أبداً في SQL بلا تعقيم، ولا تعرضه بـ |safe.

رسائل Flash

Flash هي رسالة قصيرة تُخزَّن في الجلسة (session)، ثم تُعرض في الصفحة التالية مرة واحدة. إنها الحل الأمثل لرسائل "تم الحفظ بنجاح" أو "البريد غير صالح" بعد إعادة التوجيه.

flash()

  • تخزين رسالة في الجلسة
  • تظهر في الطلب التالي
  • ثم تُحذف تلقائياً
  • تقبل فئة (category)

get_flashed_messages

  • قراءة الرسائل المخزّنة
  • في القالب
  • تُستدعى مرة واحدة عادة
  • تُفرّغ بعد القراءة

secret_key

  • إلزامي لـFlash
  • لتوقيع الجلسة
  • قيمة عشوائية طويلة
  • لا تُرفع إلى Git

الفئات

  • success للنجاح
  • error للفشل
  • info للمعلومات
  • warning للتحذير
app.py — إعداد key + استخدام Flash PYTHON 
import os
from flask import Flask, render_template, request, redirect, url_for, flash

app = Flask(__name__)
app.secret_key = os.environ.get("SECRET_KEY", "dev-secret-change-me")


@app.route("/contact", methods=["GET", "POST"])
def contact():
    if request.method == "POST":
        name = request.form.get("name", "").strip()
        email = request.form.get("email", "").strip()

        # تحقق
        if not name or not email:
            flash("يُرجى ملء جميع الحقول", "error")
            return redirect(url_for("contact"))

        if "@" not in email:
            flash("صيغة البريد غير صحيحة", "error")
            return redirect(url_for("contact"))

        # نجاح
        flash(f"شكراً {name}، تم استلام رسالتك", "success")
        return redirect(url_for("contact"))

    return render_template("contact.html")

بدون secret_key سيتعطل Flash: flash() يستخدم الجلسة (session)، والجلسة تحتاج secret_key للتوقيع. بدونها ستحصل على RuntimeError: The session is unavailable because no secret key was set. ضع قيمة عشوائية طويلة في التطوير، واقرأها من متغير بيئة في الإنتاج.
لماذا Flash وليس تمرير خطأ في render_template مباشرة؟ لأننا نستخدم Post/Redirect/Get. بعد كل POST نعيد التوجيه إلى نفس الصفحة، فلا تظهر رسالة من الاستدعاء السابق. Flash يخزّنها في الجلسة لتظهر في الطلب التالي (بعد الـredirect).

التحقق في الخادم

في المحاضرة الثامنة تعلّمنا التحقق من النماذج في الواجهة الأمامية بـJavaScript. ذلك تحسينٌ للتجربة، لكنه ليس أماناً: يمكن تجاوزه بسهولة. التحقق الحقيقي يجب أن يكون في الخادم، لأن هذا هو المكان الذي لا يمكن للمستخدم تجاوزه.

تحقق شائع

  • الحقل غير فارغ
  • الطول الأدنى والأقصى
  • صيغة البريد
  • المدى الرقمي

تحقق منطقي

  • البريد غير مستخدم مسبقاً
  • المستخدم له صلاحية
  • الطلب موجود
  • لا يمكن شراء سلعة غير متوفرة

تحقق أمني

  • تنقية HTML المرفوع
  • منع حقن SQL (المعاملات)
  • منع CSRF
  • التحقق من الملفات المرفوعة

لا تعتمد على الواجهة

  • يمكن تعطيل JavaScript
  • يمكن إرسال طلب مباشر
  • أدوات المطور تعدّل كل شيء
  • الخادم هو خط الدفاع
التحقق الكامل في الخادم PYTHON 
import re
from flask import Flask, render_template, request

app = Flask(__name__)

EMAIL_RE = re.compile(r"^[^\s@]+@[^\s@]+\.[^\s@]+$")


def validate_register(username, email, password):
    """تُرجع قاموساً من الأخطاء. فارغ = صحيح."""
    errors = {}

    if not username:
        errors["username"] = "الاسم مطلوب."
    elif len(username) < 3:
        errors["username"] = "الاسم قصير جداً (3 أحرف على الأقل)."
    elif len(username) > 30:
        errors["username"] = "الاسم طويل جداً (30 حرفاً كحد أقصى)."

    if not email:
        errors["email"] = "البريد الإلكتروني مطلوب."
    elif not EMAIL_RE.match(email):
        errors["email"] = "صيغة البريد غير صحيحة."

    if not password:
        errors["password"] = "كلمة المرور مطلوبة."
    elif len(password) < 8:
        errors["password"] = "كلمة المرور قصيرة (8 أحرف على الأقل)."

    return errors


@app.route("/register", methods=["GET", "POST"])
def register():
    errors = {}
    values = {"username": "", "email": ""}

    if request.method == "POST":
        username = request.form.get("username", "").strip()
        email = request.form.get("email", "").strip()
        password = request.form.get("password", "")

        values["username"] = username
        values["email"] = email

        errors = validate_register(username, email, password)

        if not errors:
            # هنا: حفظ في قاعدة البيانات (لاحقاً)
            return render_template("register_ok.html", username=username)

    return render_template("register.html", errors=errors, **values)

معيار الإنجاز: جميع القوالب ترث من base.html. لا يوجد HTML مكرر في الترويسة أو التذييل. الروابط كلها عبر url_for. النموذج يعمل ويستقبل البيانات. رسائل Flash تظهر وتختفي بعد عرضها. عند الفشل، المستخدم يعيد الإرسال من نفس الصفحة بدون فقدان السياق.

أخطاء شائعة ونصائح

نسيان {% extends %} أولاً

{% extends "base.html" %} يجب أن يكون أول سطر. أي شيء قبله — حتى مسافة — يسبب TemplateSyntaxError.

نسيان namespace

في render_template("home.html", name=n)، استخدم n داخل القالب كـ{{ n }}، لا {{ name }}. اسم المعامل هو ما يصل.

لا secret_key

flash() يحتاج جلسة، والجلسة تحتاج app.secret_key. بدونه: RuntimeError: session unavailable.

نسيان methods

مسار يستقبل POST يجب أن يعلن methods=["GET","POST"]. بدونه يرفض الطلب بـ405.

مسارات يدوية في القالب

href="/static/style.css" أو "/about" تعمل أحياناً وتنكسر أحياناً. استخدم url_for دائماً.

استخدام |safe مع مدخلات

{{ comment | safe }} على نص من المستخدم = ثغرة XSS. Jinja يهرّب تلقائياً — لا تعطّل هذا السلوك إلا لـ HTML تكتبه أنت.

نسخ نموذج بلا name

نسيان name="..." في حقل يعني أنه لن يُرسل. تحقّق من كل حقل: name وid مختلفان، وكلاهما مهم.

البحث في مجلد خاطئ

Flask يبحث في templates/. لو وضعت home.html في الجذر، ستحصل على TemplateNotFound. تحقق من اسم المجلد وحالة الحروف.

نصائح ذهبية:
• استخدم debug=True أثناء التطوير فقط.
• في كل مرة تنشئ قالباً جديداً، ابدأ بـ{% extends %}.
• مرّر قاموساً لقيم الخطأ بدل نصوص متعددة.
• تحقق من request.method قبل قراءة البيانات.
• دائمًا استخدم .get() بدل [].
• استخدم |safe مرة واحدة في السنة.

ملخص المحاضرة

  • Jinja2 هو template engine يعمل مع Flask لتحويل HTML قبل الإرسال.
  • {{ }} لطباعة قيمة، و{% %} للتحكم (if، for، block).
  • {# #} للتعليقات التي لا تُرسل للمتصفح.
  • render_template("name.html", key=value, ...) يمرّر البيانات للقالب.
  • وراثة القوالب: {% extends %} + {% block %} تمنع تكرار الترويسة/التذييل.
  • url_for يولّد المسارات ويعمل مهما تغيّرت.
  • ملفات CSS وJS والصور توضع في static/ وتُربط بـurl_for('static', filename='...').
  • النماذج: POST للبيانات الحساسة، GET للبحث والفلاتر.
  • request.form لـPOST، request.args لـGET، request.files للملفات.
  • .get('field', '') أأمن من ['field'] لأنه لا يرفع KeyError.
  • Flash يحتاج app.secret_key، ويُعرض في base.html عبر get_flashed_messages.
  • التحقق يكون في الخادم دائماً — لا يمكن تجاوزه.
  • عند الفشل: استخدم PRG (Post/Redirect/Get) مع Flash لعرض رسالة الخطأ.

تقييم سريع

1) ما الفرق بين {{ }} و{% %} في Jinja؟

{{ }} تعبير يُطبع في الناتج (قيمة متغير، نتيجة عملية، استدعاء دالة). {% %} كتلة تحكم لا تُطبع شيئاً: if، for، block، extends، include.

2) لماذا نستخدم url_for بدل كتابة المسارات يدوياً؟

لأن url_for يولّد المسار الصحيح تلقائياً، ويعمل حتى لو غيّرت @app.route أو نشرت التطبيق تحت subpath. الكتابة اليدوية تنكسر بسهولة، خاصة مع static/.

3) ما الفرق بين request.form وrequest.args؟

request.form يحتوي بيانات POST (جسم الطلب). request.args يحتوي بيانات GET (query string في الـURL، مثل ?q=python). لكل مصدر استخدامه: POST للبيانات الحساسة، GET للبحث والفلاتر.

4) لماذا نحتاج app.secret_key قبل استخدام Flash؟

لأن Flash يخزّن الرسائل في الجلسة (session)، والجلسة ملف توقعه Flask بـsecret_key لمنع التلاعب. بدونها، لا يستطيع Flask تشفير أو التحقق من الجلسة، فيرفع RuntimeError.

5) لماذا التحقق في الواجهة الأمامية لا يكفي أمنياً؟

لأنه يمكن تجاوزه بسهولة: تعطيل JS، تعديل الحقول بأدوات المطور، إرسال طلب مباشر بـcurl أو Postman. التحقق الحقيقي يجب أن يكون في الخادم، لأنه المكان الوحيد الذي يتحكم به المطور.
