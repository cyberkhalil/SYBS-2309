ما هي JavaScript ودورها في الويب

HTML يبني البنية، وCSS تنسّق الشكل، وJavaScript تضيف السلوك والتفاعل. هذه ثلاثية الويب. باختصار: JavaScript هي اللغة التي تجعل الصفحة حيّة بعد تحميلها في المتصفح.

HTML

  • البنية والمعنى
  • عناوين، فقرات، روابط، نماذج
  • يُقرأ من أعلى إلى أسفل
  • لا يتفاعل من تلقاء نفسه

CSS

  • الشكل والعرض
  • الألوان، الخطوط، التخطيط
  • تفاعل بصري محدود عبر :hover
  • لا تُجري حسابات ولا منطقاً

JavaScript

  • السلوك والتفاعل
  • تحسب، تتحقق، تعدّل الصفحة
  • تتفاعل مع النقر والإدخال
  • تتواصل مع الخادم لاحقاً (fetch)

أمثلة على ما تفعله JavaScript في أي موقع تقريباً: قوائم منسدلة، تبويبات، سلايدر، تحقق فوري من النماذج، تحميل محتوى دون إعادة تحميل الصفحة، إشعارات، وضع داكن/فاتح، وآلاف التفاعلات اليومية.

ملاحظة مهمة: JavaScript ليست Java. التشابه في الاسم فقط (لأسباب تسويقية تاريخية). اللغتان مختلفتان تماماً في التصميم والاستخدام.

في المتصفح

  • تعمل عبر محرّك JS في المتصفح
  • تصل إلى DOM وأحداث الصفحة
  • يمكنها قراءة التخزين المحلي
  • مقيّدة بسياسة أمان المتصفح

خارج المتصفح

  • Node.js يشغّلها على الخادم
  • نفس اللغة، بيئة مختلفة
  • لا DOM، لكن ملفات وشبكة
  • موجودة لكن ليست محور هذا المساق

إضافة JavaScript إلى HTML

نضيف JavaScript إلى HTML بثلاث طرق، تماماً كما في CSS: ضمني داخل السمة، وداخلي داخل وسم <script>، وخارجي في ملف .js منفصل. الطريقة الأفضل دائماً هي الملف الخارجي.

الطرق الثلاث HTML 
<!-- 1) ضمني: على العنصر — للتجربة فقط -->
<button onclick="alert('مرحباً')">اضغط</button>

<!-- 2) داخلي: وسم script داخل الصفحة -->
<script>
    console.log('هذا سكربت داخلي');
</script>

<!-- 3) خارجي: الأفضل -->
<script src="main.js" defer></script>

Inline

  • داخل السمة onclick أو onchange…
  • لا تُعاد استخدامها
  • تُلوّث HTML
  • مقبولة للتوضيح فقط

Internal

  • داخل <script> في الصفحة
  • مقبولة لصفحة واحدة
  • لا تُخزَّن مؤقتاً
  • يفضّل تجنبها عند التكرار

External ✔

  • ملف .js منفصل
  • يُربط عبر <script src="main.js">
  • قابل للتخزين المؤقت
  • الأفضل في المساق دائماً

أين نضع وسم <script>؟ في نهاية <body> أو في <head> مع السمة defer. السبب أن السكربت عندما يعمل قبل بناء DOM، لن يجد العناصر التي يريد التعامل معها. السمة defer تُخبر المتصفح أن يُنزّل السكربت بالتوازي، لكن ينفّذه بعد بناء DOM كاملاً.

index.html HTML 
<body>
    <h1>مرحباً</h1>

    <!-- الخيار الأفضل: في نهاية body -->
    <script src="main.js"></script>

    <!-- أو في head مع defer -->
    <!-- <script src="main.js" defer></script> -->
</body>
تحذير: إذا وضعت <script src="…"> في head بدون defer أو async، فقد يحاول السكربت الوصول إلى عناصر DOM قبل وجودها، وترى أخطاء Cannot read property of null. الحل: defer أو نهاية body.

المتغيرات: let وconst

المتغير هو اسم مرتبط بقيمة. بدونه لا يمكن أن نحتفظ بأي بيانات ونعيد استخدامها. JS الحديثة تستخدم let و const. الكلمة القديمة var موجودة، لكن لا ننصح بها في المشاريع الحديثة لأن سلوك نطاقها مربك.

let

  • متغير قابل لإعادة التعيين
  • عندما تعرف أن القيمة ستتغير
  • مثال: عدّاد، مجموع، نص يُبنى تدريجياً
  • لا يمكن إعادة تعريفه في نفس النطاق

const

  • قيمة ثابتة لا تُعاد
  • الخيار الافتراضي في المشاريع
  • مثال: نِسب ثابتة، عناصر ثابتة
  • لا يمكن إعادة تعيينها بعد التعريف
variables.js JS 
// const للقيم الثابتة
const TAX_RATE = 0.05;
const APP_NAME = 'حاسبة البقشيش';

// let للقيم المتغيرة
let count = 0;
let tip = 0;

// تعديل قيمة let
count = count + 1;
tip = 25;

// محاولة تعديل const تُحدث خطأ
// TAX_RATE = 0.10;  // TypeError

// مقارنة سريعة في Console
console.log(APP_NAME, count, tip);
قاعدة عملية: استخدم const افتراضياً، ولا تستخدم let إلا إذا كنت تعرف أن القيمة ستتغير فعلاً. هذا يجعل الكود أسهل في القراءة والصيانة، لأنك تعرف فوراً أي قيم يُتوقع تعديلها.
naming.js JS 
// أسماء جيدة (camelCase)
const userName = 'سارة';
const finalTotal = 125;
let itemsCount = 3;
let isSubscribed = false;

// أسماء سيئة
const x = 'سارة';        // غير واضح
const DATA1 = 125;       // لا معنى
let aa_bb = 3;           // صعب القراءة
أخطاء شائعة:
• أسماء بحروف عربية: JavaScript تقبلها، لكنها تسبب صداعاً في المسارات والتبديل بين اللغات.
• أسماء تبدأ برقم: let 1x خطأ.
• كلمات محجوزة: let if = 5; خطأ.

أنواع البيانات

JavaScript لغة ذات أنواع ديناميكية: المتغير يأخذ نوع القيمة التي فيه. أهم أنواع البيانات التي سنستخدمها:

النوع أمثلة ملاحظة
string 'مرحباً'، "Hello"، `Hi` نص، يمكن أن يكون بين علامات مفردة أو مزدوجة أو backticks
number 42، 3.14، -7 لا يوجد فرق بين صحيح وعشري في JS
boolean true، false قيمة صواب/خطأ
undefined متغير معلن بلا قيمة الأنواع "غير المعرفة"
null قيمة فارغة متعمدة تأتي من صاحب الكود، لا من JS
array [1, 2, 3] قائمة مرتبة من القيم
object { name: 'سارة', age: 20 } كائن بخصائص مفتاحية (لاحقاً)
data-types.js JS 
// النصوص
const name = 'سارة';
const greeting = "أهلاً";
const template = `مرحباً ${name}`;   // سنشرحها بعد قليل

// الأرقام
const age = 20;
const price = 49.99;

// القيم المنطقية
const isStudent = true;
const isAdmin = false;

// التحقق من النوع باستخدام typeof
console.log(typeof 'سارة');    // string
console.log(typeof 42);         // number
console.log(typeof true);       // boolean
console.log(typeof undefined);  // undefined
console.log(typeof null);       // object (سلوك تاريخي غريب)
console.log(typeof [1,2,3]);    // object
تحويل الأنواع: يمكن تحويل النص إلى رقم بـ Number('14') أو parseInt('14')، والرقم إلى نص بـString(14) أو (14).toString(). كن حذراً: Number('abc') ترجع NaN (ليس رقماً)، وهو مؤشر على إدخال غير صالح.

العمليات الحسابية والمقارنة والمنطقية

JavaScript تعرف العمليات الحسابية المعتادة، وعمليات المقارنة، والعمليات المنطقية. هذه العمليات ستكون العصب الأساسي لكل شروطك وقراراتك لاحقاً.

حسابية

  • + جمع (وأيضاً دمج نصوص)
  • - طرح
  • * ضرب
  • / قسمة
  • % باقي القسمة
  • ** أس

مقارنة

  • === يساوي (قيمة ونوع)
  • !== لا يساوي (قيمة ونوع)
  • >، <
  • >=، <=
  • == يساوي (بعد تحويل النوع) — تجنّبها

منطقية

  • && و (كلاهما صحيح)
  • || أو (أحدهما صحيح)
  • ! نفي
  • تُستخدم بكثافة في الشروط
operators.js JS 
// حسابية
const a = 10;
const b = 3;

console.log(a + b);      // 13
console.log(a - b);      // 7
console.log(a * b);      // 30
console.log(a / b);      // 3.3333...
console.log(a % b);      // 1
console.log(a ** b);     // 1000

// مقارنة — استخدم === دائماً
console.log(5 === 5);        // true
console.log(5 === '5');      // false  (نوع مختلف)
console.log(5 == '5');       // true   (تحويل نوع — تجنّبها)
console.log(5 !== 3);        // true
console.log(10 > 5);         // true

// منطقية
const isAdult = true;
const hasTicket = false;

console.log(isAdult && hasTicket);  // false
console.log(isAdult || hasTicket);  // true
console.log(!isAdult);              // false
خطأ شائع: استخدام == بدل ===. '5' == 5 ترجع true لأن JS تحوّل النوع تلقائياً. هذا يُنتج أخطاء منطقية غامضة. استخدم === دائماً.
ملاحظة على +: هي عملية "متعددة الأغراض":
5 + 3 = 8 (جمع)
'5' + 3 = '53' (دمج نصوص)
انتبه، فهي مصدر أخطاء متكرر عند التعامل مع مدخلات النماذج التي تأتي دائماً كنصوص. حلّل النص إلى رقم بـNumber() أولاً.

Template literals والنصوص

في الإصدارات القديمة، كان دمج النصوص مملاً: 'مرحباً ' + name + '، عمرك ' + age. JS الحديثة وفّرت Template literals باستخدام backticks ` مع ${ } لإدراج القيم داخل النص مباشرة.

template-literals.js JS 
const name = 'سارة';
const age = 20;

// الطريقة القديمة
const msgOld = 'مرحباً ' + name + '، عمرك ' + age + ' سنة';

// الطريقة الحديثة (Template literal)
const msgNew = `مرحباً ${name}، عمرك ${age} سنة`;

console.log(msgNew);

// ميزات إضافية
const multiLine = `السطر الأول
السطر الثاني
السطر الثالث`;
console.log(multiLine);

// يمكن وضع تعبيرات داخل ${}
const sum = `المجموع: ${10 + 5}`;
console.log(sum);   // المجموع: 15

مزايا

  • دمج نصوص أنظف
  • دعم الأسطر المتعددة تلقائياً
  • إمكانية إدراج تعبيرات لا مجرد متغيرات
  • الطريقة المفضّلة في المساق

انتبه

  • Backticks ` ليست علامات اقتباس عادية
  • على لوحة المفاتيح: تحت زر Esc عادة
  • الخلط بينها وبين ' يُنتج أخطاء غامضة
  • لا تنسَ إغلاقها
نص-متعدد-الأسطر.html HTML+JS 
// إدراج محتوى HTML بالكامل عبر template literal
const card = `
    <article class="card">
        <h2>${name}</h2>
        <p>العمر: ${age}</p>
    </article>
`;
document.body.innerHTML = card;

المصفوفات

المصفوفة (array) هي قائمة مرتبة من القيم. تفيدنا حين نريد تجميع قيم متعددة في متغير واحد: قائمة أسماء، درجات، منتجات، إلخ. العناصر تُفهرَس من 0، لا من 1.

arrays.js JS 
// إنشاء مصفوفة
const skills = ['HTML', 'CSS', 'JavaScript'];
const numbers = [10, 20, 30, 40];

// الوصول إلى عنصر (يبدأ من 0)
console.log(skills[0]);      // HTML
console.log(skills[2]);      // JavaScript

// الطول
console.log(skills.length);  // 3

// آخر عنصر
console.log(skills[skills.length - 1]);  // JavaScript

// إضافة عنصر (تعديل مصفوفة const مسموح)
skills.push('Python');
console.log(skills);         // HTML, CSS, JavaScript, Python

// حذف آخر عنصر
skills.pop();
console.log(skills);

// الدوران عبر المصفوفة
for (let i = 0; i < skills.length; i++) {
    console.log(i, skills[i]);
}

إضافة وحذف

  • push(x) إضافة في الأخير
  • unshift(x) إضافة في الأول
  • pop() حذف من الأخير
  • shift() حذف من الأول

فحص

  • includes(x) هل يحتوي على x؟
  • indexOf(x) أين موقعه؟
  • length عدد العناصر
  • join(sep) دمج في نص

تحويل (لاحقاً)

  • map تحويل كل عنصر
  • filter تصفية العناصر
  • forEach المرور على العناصر
  • ستراها في المحاضرة القادمة
ملاحظة على const والمصفوفات: const skills = [...] تعني أن المرجع ثابت، لا أن المحتوى ثابت. يمكنك push وpop لأنك تعدّل المحتوى، لكن لا يمكنك إعادة تعيين المصفوفة كلها بـskills = [];.

Console وتصحيح الأخطاء

Console هو أفضل صديق لك. هو محرّك التصحيح الأولي. افتحه بـF12 ثم تبويب Console. تكتب فيه أي تعبير JS وتُنفّذه فوراً، وترى مخرجات console.log من سكربتاتك.

console.js JS 
// طباعة بسيطة
console.log('مرحباً بالعالم');

// طباعة قيم متعددة
const name = 'سارة';
const age = 20;
console.log('الاسم:', name, '— العمر:', age);

// طباعة template literal
console.log(`الاسم ${name} والعمر ${age}`);

// أنواع مختلفة
console.info('رسالة معلومات');
console.warn('تحذير');
console.error('خطأ واضح');

// جدول مصفوفة (مفيد للمصفوفات والكائنات)
const skills = ['HTML', 'CSS', 'JS'];
console.table(skills);

// توقيت عملية
console.time('loop');
for (let i = 0; i < 10000; i++) {}
console.timeEnd('loop');

console.log

  • الطباعة الأساسية
  • ملائمة للفحص السريع
  • لا تُستخدم بدلُّ التصحيح المنهجي
  • احذفها قبل التسليم

قراءة الأخطاء

  • الخطأ يظهر بالأحمر في Console
  • السطر الذي حصل فيه الخطأ ظاهر
  • اقرأ النص حرفياً قبل التخمين
  • ReferenceError يعني متغيراً غير معرّف

أنواع الأخطاء

  • SyntaxError خطأ كتابي
  • ReferenceError متغير مفقود
  • TypeError نوع غير مناسب
  • RangeError خارج النطاق

نصائح

  • اطبع القيمة قبل استخدامها
  • اعزل السطر المشكوك فيه
  • علّق أجزاءً لتحديد مصدر الخطأ
  • لا تخف من الرسائل، اقرأها
قاعدة ذهبية: عندما لا يعمل الكود، أول سؤال تسأله لنفسك: "هل طبعت القيم فعلاً لأتأكد من صحتها؟". 80% من الأخطاء تُكشف بمجرد console.log قبل السطر الذي يبدو أنه يفشل.

التطبيق العملي

المطلوب اليوم كتابة ثلاثة سكربتات صغيرة، تُشغّلها في Console أولاً، ثم تُنقل إلى ملف main.js مع وظيفة تشغيل تعرض النتائج.

    • عرّف const fahrenheit = celsius × 9 ÷ 5 + 32.
    • اطبع النتيجة بـtemplate literal مع الوحدة.
  6. أنشئ السكربت الثالث: منسّق أسماء.
    • عرّف const firstName وconst lastName.
    • استخدم trim() لإزالة الفراغات.
    • استخدم toUpperCase() على الأحرف الأولى.
    • اطبع الاسم الكامل بالصيغة: سارة أحمد.
  7. افتح الصفحة في المتصفح، ثم افتح Console.
  8. تأكد من ظهور نتائج السكربتات الثلاثة.
  9. جرّب تغيير القيم ومراقبة النتائج في Console.
  10. جرّب إدخال قيمة نصية مكان قيمة رقمية، ولاحظ ما يحدث.
  11. أرفق lab6.js وصورة من Console تعرض المخرجات.

// 1) حاسبة بقشيش
const bill = 120;
const tipPercent = 15;

const tip = (bill * tipPercent) / 100;
const total = bill + tip;

console.log(`فاتورة: ${bill} | بقشيش: ${tip} | المجموع: ${total}`);

// 2) محول حرارة
const celsius = 25;
const fahrenheit = (celsius * 9) / 5 + 32;

console.log(`${celsius}°C = ${fahrenheit}°F`);

// 3) منسق أسماء
const firstName = '  سارة ';
const lastName = '  أحمد  ';

const cleanFirst = firstName.trim();
const cleanLast = lastName.trim();
const fullName = `${cleanFirst} ${cleanLast}`;

console.log(`الاسم الكامل: ${fullName}`);
معيار الإنجاز: Console يعرض ثلاث نتائج واضحة، لا أخطاء حمراء، وكل سكربت يستخدم const وlet بشكل صحيح، والأسماء واضحة، والقيم الرقمية معالجة كأرقام لا نصوص.

أخطاء شائعة ونصائح

استخدام == بدل ===

'5' == 5 ترجع true بسبب تحويل النوع، وهذا يسبب أخطاء منطقية غامضة. استخدم === دائماً.

خلط علامات النصوص

'مرحباً" — بداية بعلامة وإغلاق بأخرى. JS لن تفهم. التزم بنفس العلامة في الطرفين. وتذكّر أن ` (backticks) شيء ثالث مختلف للـ template literals.

جمع نص ورقم

'10' + 5 ترجع '105'، لأن + مع نص تعني دمجاً. حوّل النص إلى رقم بـNumber() أو parseInt() قبل الجمع.

إعادة تعريف const

const x = 5; x = 10; خطأ. استخدم let إذا كنت تنوي تعديل القيمة، أو عرّف متغيراً جديداً.

نسيان الفاصلة المنقوطة

JS في الغالب تتسامح (Automatic Semicolon Insertion)، لكنها قد تسبب أخطاء غامضة. اكتب ; في نهاية كل جملة — عادة صحية أفضل.

تشغيل السكربت قبل DOM

إذا وضعت السكربت في head بدون defer، أو في body قبل العناصر، فلن يجدها. الحل: نهاية body أو defer.

نصائح سريعة:
• اقرأ الخطأ في Console حرفياً.
• اطبع القيم قبل استخدامها.
• رتّب السكربت في أقسام بتعليقات.
• استخدم typeof عند الشك في نوع قيمة.
• سمّ المتغيرات بأسماء معبّرة.

ملخص المحاضرة

  • JavaScript تضيف السلوك للصفحة، بعد HTML للبنية وCSS للشكل.
  • نضيفها عبر external (الأفضل)، أو internal، أو inline.
  • ضع السكربت في نهاية body أو استخدم defer.
  • const للقيم الثابتة، وlet للقيم المتغيرة.
  • الأنواع الأساسية: string، number، boolean، array، undefined، null.
  • عمليات حسابية ومقارنة (=== دائماً) ومنطقية.
  • Template literals بـ`...${expr}...` لأنظف نصوص.
  • المصفوفات تُفهرَس من 0، وتدعم push، pop، length.
  • console.log هو سلاحك الأول للتصحيح.
  • اقرأ أنواع الأخطاء: SyntaxError، ReferenceError، TypeError.

تقييم سريع

1) ما الفرق بين let وconst؟

let يسمح بإعادة تعيين القيمة لاحقاً، وconst لا يسمح بذلك بعد التعريف. قاعدة عملية: استخدم const افتراضياً، ولا تستخدم let إلا إذا كانت القيمة ستتغير.

2) لماذا نفضّل === على ==؟

لأن === يقارن القيمة والنوع معاً دون تحويل تلقائي، بينما == يحوّل النوع تلقائياً. هذا التحويل يسبب أخطاء منطقية غامضة، مثل اعتبار '5' و5 متساويين.

3) أين نضع وسم <script> ولماذا؟

في نهاية <body>، أو في <head> مع السمة defer. السبب أن السكربت قد يحتاج عناصر DOM التي لم تُبنَ بعد، فيحدث خطأ Cannot read property of null.

4) ماذا يطبع typeof null؟

يطبع "object". هذه قضية تاريخية معروفة في JavaScript، وليست خطأ اليوم. للتحقق من null استخدم مقارنة صريحة: value === null.

5) ما وظيفة console.log؟

طباعة رسالة أو قيمة في تبويب Console بأدوات المطور. هي أداة التصحيح الأساسية، وتساعد في فحص القيم أثناء تنفيذ السكربت.
