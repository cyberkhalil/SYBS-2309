المحاضرة 8: DOM والأحداث والتحقق من المدخلات

في المحاضرة السابقة تعلمنا المنطق البرمجي والدوال. اليوم نصل إلى اللحظة التي تصبح فيها الصفحة تفاعلية حقيقية: نتعرف على DOM — التمثيل الشجري للصفحة الذي يستطيع JavaScript التعامل معه — ثم نتعلم كيف نختار العناصر بـ querySelector وgetElementById، ونعدّل المحتوى والخصائص والأصناف، ونستجيب للأحداث (نقر، إدخال، إرسال نموذج) عبر addEventListener، وننهي ببناء تحقق من النماذج في الواجهة الأمامية مع رسائل خطأ واضحة وقابلة للوصول — ليس هذا نهاية الأمان، بل بدايته، والتحقق النهائي يبقى في الخادم.

أهداف المحاضرة ومخرجات التعلم

بنهاية هذه المحاضرة ستكون قادراً على قراءة صفحة HTML والتعامل معها برمجياً: تختار أي عنصر تريد، تغيّر نصه أو خصائصه أو أصنافه، تستمع لنقرات المستخدم وإدخالاته، تتحقق من صحة مدخلات النموذج قبل الإرسال، وتُظهر رسائل خطأ واضحة وقابلة للوصول. هذه المهارات هي جوهر أي تطبيق ويب تفاعلي — وهي ما سيمكّنك لاحقاً من فهم كيف يستقبل Flask البيانات من الواجهة.

مخرجات معرفية

  • شرح ما هو DOM وكيف يبنيه المتصفح
  • التمييز بين querySelector وgetElementById
  • فهم دورة حياة الحدث وكائن event
  • معرفة الفرق بين textContent وinnerHTML
  • إدراك أن تحقق الواجهة ليس أماناً كاملاً

مخرجات عملية

  • اختيار العناصر وتعديل محتواها
  • الاستماع لأحداث click وsubmit وinput
  • منع إرسال النموذج عبر e.preventDefault()
  • بناء تحقق مخصص من الاسم والبريد وكلمة المرور
  • عرض رسائل خطأ مرتبطة بالحقول

قيمة مهنية

  • تجنّب أخطاء null عند تشغيل السكربت قبل DOM
  • كتابة مستمعات أحداث نظيفة وغير متكررة
  • تصميم نماذج تفاعلية صديقة للمستخدم
  • الاستعداد لمحاضرة الامتحان النصفي (مراجعة الأسابيع 1–8)

ما هو DOM وكيف يبنيه المتصفح

DOM اختصار Document Object Model — نموذج كائنات المستند. هو التمثيل البرمجي للصفحة كنظام من الكائنات المتداخلة، أي شجرة. عندما يقرأ المتصفح ملف HTML، يحوّله إلى هذا النموذج، ويصبح كل وسم عنصراً (Element) له خصائص ويمكن التعامل معه عبر JavaScript.

المتصفح لا يقرأ HTML حرفياً عند تنفيذ JavaScript، بل يقرأ الشجرة التي بناها من HTML. أي تعديل تجريه JavaScript على DOM ينعكس مباشرة على الصفحة المرئية — وهذا هو سر التفاعل.

ملف HTML

نص مكتوب في الملف، لا يفهمه JavaScript مباشرة.

يُحلَّل يُرسم

شجرة DOM

كائنات مترابطة: html ← body ← عناصر ← نصوص.

DOM Tree — مفهوم TREE 
document
└── html
    ├── head
    │   ├── meta (charset)
    │   ├── title
    │   └── link (stylesheet)
    └── body
        ├── header
        │   └── h1 → "مرحباً"
        ├── main
        │   ├── p → "فقرة نص"
        │   └── ul
        │       ├── li → "HTML"
        │       └── li → "CSS"
        └── footer

Element

  • كل وسم HTML يصبح عنصراً
  • له خصائص (attributes) وأبناء
  • عليه نطبّق التعديلات
  • أمثلة: <h1>، <p>، <img>

Text Node

  • النص داخل العنصر
  • ليس عنصراً بل عقدة نصية
  • نقرأه بـtextContent
  • يظهر في الصفحة المرئية

document

  • الجذر البرمجي للشجرة
  • منه تبدأ كل عمليات البحث
  • مثال: document.body
  • موجود تلقائياً في المتصفح

متى يُبنى DOM؟

  • يتدرّج أثناء قراءة HTML
  • ليس كاملاً حتى يصل المتصفح للنهاية
  • لهذا نضع السكربت في نهاية body
  • أو في head مع defer
مشكلة شائعة: تشغيل السكربت قبل اكتمال بناء DOM يُنتج خطأ Cannot read properties of null. السبب أن document.querySelector('h1') تُرجع null لأن العنصر لم يُبنَ بعد. الحل: defer أو نهاية body.

اختيار العناصر

كل عملية في DOM تبدأ بـاختيار: نحدد عنصراً موجوداً في الصفحة ثم نتعامل معه. الأدوات الأساسية لذلك:

الأداة ترجع المثال
getElementById('x') عنصر واحد بـ id document.getElementById('hero')
querySelector('.c') أول عنصر يطابق المحدد document.querySelector('.card')
querySelectorAll('.c') كل العناصر المطابقة (NodeList) document.querySelectorAll('.card')
getElementsByClassName('c') كل عناصر الصنف (HTMLCollection حية) أقل استخداماً اليوم
getElementsByTagName('p') كل عناصر الوسم نادر استخدامه
element.children أبناء عنصر مباشرون card.children
element.parentElement الأب المباشر btn.parentElement
element.closest('.c') أقرب سلف يطابق المحدد link.closest('article')
selecting.js JS 
// اختيار عنصر واحد
const title = document.querySelector('h1');

// اختيار بـ id
const hero = document.getElementById('hero');

// اختيار كل البطاقات
const cards = document.querySelectorAll('.card');

// المرور عليها
cards.forEach(card => {
    console.log(card.textContent);
});

// تحويل NodeList إلى مصفوفة (إذا احتجت)
const arr = Array.from(cards);
console.log(arr.length);

querySelector

  • يقبل أي محدد CSS
  • يعيد أول تطابق فقط
  • مرن جداً
  • الخيار اليومي

querySelectorAll

  • يعيد NodeList من كل التطابقات
  • يدعم forEach
  • مفيد للبطاقات والقوائم
  • ثابت (لا يتحدث تلقائياً)

احترس من null

  • إذا لم يجد العنصر يرجع null
  • محاولة الوصول لخاصية أو null = خطأ
  • تحقق قبل الاستخدام أو استخدم ?.
  • مثال: title?.textContent
قاعدة عملية: استخدم querySelector عندما تحتاج عنصراً أو محدداً معقداً، وquerySelectorAll عندما تحتاج مجموعة. تجنّب getElementsByClassName في المشاريع الحديثة لأن مجموعتها "حية" — تتغير تلقائياً عند تعديل DOM، وهذا يسبب مفاجآت.

تعديل المحتوى والخصائص والأصناف

بعد اختيار العنصر، نستطيع تعديل عدة جوانب: المحتوى، الخصائص (attributes)، الأصناف، والأنماط. كل جانب له واجهته الخاصة في DOM.

textContent

  • يقرأ أو يكتب النص الخام
  • يتجاهل وسوم HTML داخله
  • آمن ضد XSS تقريباً
  • الخيار المفضل للنصوص

innerHTML

  • يقرأ أو يكتب HTML كامل
  • يفسّر الوسوم وينشئ عناصر
  • خطر XSS إذا جاء من المستخدم
  • استخدمه بحذر شديد

setAttribute / removeAttribute

  • تعديل خصائص مثل href وsrc
  • مثال: a.href = 'https://...'
  • يمكن القراءة بـ getAttribute
  • الخاصية المباشرة أسرع في الغالب

classList

  • add('a') يضيف صنفاً
  • remove('a') يحذف صنفاً
  • toggle('a') يبدّل الحالة
  • contains('a') يتحقق
modify.js JS 
const title = document.querySelector('h1');
const card = document.querySelector('.card');
const link = document.querySelector('.hero-link');
const btn = document.querySelector('.toggle-btn');

// النص
title.textContent = 'عنوان جديد';

// الصنف
card.classList.add('active');
card.classList.remove('hidden');
card.classList.toggle('dark');       // يضيف أو يحذف
const hasActive = card.classList.contains('active');
console.log(hasActive);               // true

// الخصائص
link.href = 'https://developer.mozilla.org/ar/';
link.setAttribute('target', '_blank');
link.setAttribute('rel', 'noopener noreferrer');

// الأنماط — للأخطاء البرمجية فقط، لا للتصميم
card.style.borderColor = '#3b82f6';

// ملاحظة على textContent مقابل innerHTML
const box = document.querySelector('.box');

// آمن — يظهر النص كما هو
box.textContent = 'نص حرفي';

// خطر — إذا كان النص من المستخدم، قد يُنفّذ سكربتاً
box.innerHTML = 'نص عريض';
تحذير أمني مهم: innerHTML مع نص قادم من المستخدم (تعليق، اسم، رسالة) يفتح باب XSS. المستخدم قد يكتب <img src=x onerror=alert(1)> فيُستثمر مباشرة. القاعدة: استخدم textContent لكل ما هو نصي، وinnerHTML فقط للـHTML الذي تكتبه أنت أو تأتي من مصدر موثوق ومُنقّى.
لمسة احترافية: اجعل تعديل الأصناف هو أسلوبك الرئيسي للتفاعل. بدلاً من تغيير style.color مباشرة، أضف أو احذف صنفاً في CSS. هذا يفصل الشكل عن السلوك، ويجعل تجربة استخدامك متسقة.

الأحداث وaddEventListener

الحدث (Event) هو شيء يحدث في الصفحة: نقر، إدخال، تمرير، إرسال نموذج، تحميل. JavaScript تستطيع "الاستماع" لهذه الأحداث وتنفيذ كود استجابةً لها. الأداة الأساسية هي addEventListener.

events.js JS 
const btn = document.querySelector('.btn');
const form = document.querySelector('form');
const input = document.querySelector('#email');

// نقر
btn.addEventListener('click', () => {
    console.log('تم النقر');
});

// إرسال نموذج
form.addEventListener('submit', (e) => {
    e.preventDefault();       // منع إعادة التحميل
    console.log('داخل submit');
});

// إدخال أثناء الكتابة
input.addEventListener('input', (e) => {
    console.log('القيمة الحالية:', e.target.value);
});

// خروج العنصر من التركيز
input.addEventListener('blur', () => {
    console.log('انتهى الإدخال');
});
الحدث يُطلق عند الاستخدام الشائع
click نقر أو لمس أزرار، تبويبات، قوائم
submit إرسال النموذج التحقق قبل الإرسال
input تغيّر قيمة الحقل أثناء الكتابة تحقق فوري، عدّاد أحرف
change تغيّر قيمة ثم مغادرة الحقل قوائم، تشيك بوكس
blur / focus خروج / دخول تركيز التحقق عند المغادرة
keydown ضغط مفتاح اختصارات لوحة المفاتيح
DOMContentLoaded بناء DOM كامل بدء السكربت بأمان

e.target

  • العنصر الذي أطلق الحدث
  • مثال: حقل الإدخال ذاته
  • نقرأ قيمته بـ e.target.value
  • مفيد لمعالجة جماعية

preventDefault

  • يمنع السلوك الافتراضي للمتصفح
  • أهم استخدام: منع إرسال النموذج
  • مفيد أيضاً في منع اتباع رابط
  • يُستخدم قبل أي منطق آخر

addEventListener مقابل onclick

  • addEventListener يسمح بمستمعات متعددة
  • onclick يستبدل المستمع السابق
  • addEventListener أفضل دائماً
  • لا تستخدم السمة onclick="" في HTML

once وpassive

  • { once: true } لمستمع يعمل مرة
  • { passive: true } لتحسين الأداء
  • مفيد لأحداث scroll وtouch
  • لا يؤثر على click عادة
لا تنسَ e.preventDefault(): بدونها، سيحاول المتصفح إرسال النموذج إلى الخادم (أو إعادة تحميل الصفحة بمسار action)، وستفقد كل تعديلاتك وتحققك. ضعها في أول سطر من معالج submit.

التحقق من النماذج في الواجهة الأمامية

التحقق في الواجهة الأمامية يفعل ثلاثة أمور: يحسّن التجربة (المستخدم لا ينتظر إرسال الخادم ليعرف خطأه)، يقلل الطلبات غير الصالحة، ويُظهر رسائل واضحة. لكنه ليس أماناً. التحقق الحقيقي يبقى في الخادم.

التحقق المدمج

  • required، minlength، pattern
  • المتصفح يمنع الإرسال تلقائياً
  • رسائل مدمجة (رسائل المتصفح)
  • لا تعتمد عليه وحده

التحقق المخصص

  • نكتبه بأنفسنا في JavaScript
  • رسائل عربية واضحة في مكان محدد
  • يعمل مع novalidate
  • التحكم الكامل بالتجربة
form.html HTML 
<form id="register-form" novalidate>
    <p>
        <label for="email">البريد الإلكتروني</label>
        <input type="email" id="email" name="email" required>
        <small class="error" id="email-error" role="alert"></small>
    </p>

    <p>
        <label for="password">كلمة المرور</label>
        <input type="password" id="password" name="password"

        <small class="error" id="password-error" role="alert"></small>
    </p>

    <button type="submit">إنشاء الحساب</button>
</form>
validation.js JS 
const form = document.getElementById('register-form');
const email = document.getElementById('email');
const password = document.getElementById('password');
const emailErr = document.getElementById('email-error');
const passErr = document.getElementById('password-error');

function setError(input, errEl, message) {
    errEl.textContent = message;
    input.classList.add('invalid');
    input.setAttribute('aria-invalid', 'true');
}

function clearError(input, errEl) {
    errEl.textContent = '';
    input.classList.remove('invalid');
    input.removeAttribute('aria-invalid');
}

function validateEmail(value) {
    if (value.trim() === '') return 'البريد الإلكتروني مطلوب.';
    const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!re.test(value)) return 'صيغة البريد غير صحيحة.';
    return '';
}

function validatePassword(value) {
    if (value.length === 0) return 'كلمة المرور مطلوبة.';
    if (value.length < 8) return 'كلمة المرور يجب أن تكون 8 أحرف أو أكثر.';
    return '';
}

form.addEventListener('submit', (e) => {
    e.preventDefault();  // منع الإرسال الافتراضي

    let ok = true;

    // بريد
    const emailMsg = validateEmail(email.value);
    if (emailMsg) {
        setError(email, emailErr, emailMsg);
        ok = false;
    } else {
        clearError(email, emailErr);
    }

    // كلمة مرور
    const passMsg = validatePassword(password.value);
    if (passMsg) {
        setError(password, passErr, passMsg);
        ok = false;
    } else {
        clearError(password, passErr);
    }

    if (!ok) return;

    console.log('البيانات جاهزة للإرسال:');
    console.log({
        email: email.value,
        password: password.value
    });

    // لاحقاً: fetch أو form.submit() إلى Flask
});
مرة أخرى للتأكيد: تحقق JavaScript يمكن تجاوزه بسهولة (تعطيل JS، أدوات المطور، إرسال طلب مباشر بـcurl). تحققك في الواجهة يحسّن التجربة، لكنه ليس أماناً. في Flask لاحقاً سنكرر التحقق على الخادم.
لماذا novalidate؟ إذا كتبنا التحقق المخصص، نستخدم novalidate على النموذج لتعطيل رسائل المتصفح الافتراضية. بهذا نعرض رسائلنا العربية الموحّدة بدل رسائل المتصفح الإنجليزية المتغيرة بين المتصفحات.

رسائل خطأ مفيدة وقابلة للوصول

رسالة الخطأ ليست تفصيلاً جمالياً. هي أهم ما يراه المستخدم عند التعثر. جودة الرسالة تحدد إن كان سيعرف كيف يُصحّح الخطأ أو سيستسلم. والوصولية تجعلها مفهومة للجميع، بما فيهم من يعتمد على قارئ الشاشة.

خصائص الرسالة الجيدة

  • واضحة: تصف المشكلة بالضبط
  • قابلة للتنفيذ: تقول كيف تُصلح
  • بالعربية: لا رسائل متصفح مبهمة
  • قريبة من الحقل
  • تختفي عند التصحيح

الوصولية

  • role="alert" لقارئ الشاشة
  • aria-invalid="true" على الحقل
  • aria-describedby لربط الرسالة
  • لا تعتمد على اللون وحده

رسائل سيئة

  • "خطأ!"
  • "Invalid input"
  • "الحقل مطلوب" (أي حقل؟)
  • رسالة عامة فوق الصفحة لكل حقل

تحسين التجربة

  • تحقق عند submit لا عند كل ضغطة
  • blur خيار لطيف بعد الكتابة
  • ركز على أول حقل خاطئ
  • لا تصرخ بالأحمر في كل مكان
a11y-error.html HTML 
<p>
    <label for="email">البريد الإلكتروني</label>
    <input type="email"
           id="email"
           name="email"
           aria-describedby="email-error"
           aria-invalid="false">
    <small id="email-error"
           role="alert"
           class="error"></small>
</p>
تفصيل تقني: role="alert" يجعل قارئ الشاشة يُعلن النص فور ظهوره داخل العنصر. aria-invalid يخبر التقنيات المساعدة أن القيمة الحالية غير صحيحة. aria-describedby يربط الرسالة بالحقل. هذه الثلاثة معاً تنقل تجربة المستخدم البصري إلى المستخدم غير المبصر.

input:focus {

التطبيق العملي

المطلوب بناء صفحة تسجيل كاملة تعمل بالكامل في الواجهة الأمامية: نموذج، تحقق مخصص، رسائل خطأ عربية مرتبطة بالحقول، ومنع إعادة تحميل الصفحة عند الإرسال.

تطبيق المحاضرة 8

  1. أنشئ ملف register.html داخل مجلد web-course.
  2. اكتب مستند HTML5 كاملاً مع هيكل دلالي (header، main، footer).
  3. أضف نموذجاً فيه حقلان على الأقل:
    • البريد الإلكتروني: type="email"، required، مع <small class="error"> تحته.
    • كلمة المرور: type="password"، required، minlength="8".
    • رقم الهاتف (اختياري في التحدي): type="tel" مع pattern رقمي.
  4. أضف novalidate على <form> لتستبدل رسائل المتصفح برسائلك.
  5. في main.js (أو ملف مخصص register.js)، اكتب دالتين:
    • setError(input, errEl, msg) — تضبط النص وتضيف صنفاً وتضبط aria-invalid.
    • clearError(input, errEl) — تمسح النص وتزيل الصنف والصفة.
  6. اكتب دالتَي تحقق: validateEmail(value) وvalidatePassword(value) تُرجعان نص الخطأ أو ''.
  7. أضف form.addEventListener('submit', e => { ... }).
  8. في أول سطر من معالج submit: e.preventDefault().
  9. نفّذ التحقق على الحقلين، اعرض الرسائل، وتوقف إذا وُجد خطأ.
  10. عند النجاح: اطبع البيانات في console.log (لاحقاً سنستبدلها بـfetch إلى Flask).
  11. جرّب: إرسال فارغ، بريد بلا @، كلمة مرور 4 أحرف، ثم بيانات صحيحة.
  12. افحص الحقول بلوحة المفاتيح فقط، وتأكد أن رسائل الخطأ تُقرأ بوضوح.
  13. أرفق register.html وregister.js وصورتين: واحدة تُظهر خطأً، والأخرى نجاحاً.
register.js — هيكل البداية JS 
// ==========================================
// SYBS 2309 — المحاضرة 8 — التطبيق العملي
// ==========================================

const form = document.getElementById('register-form');
const email = document.getElementById('email');
const password = document.getElementById('password');
const emailErr = document.getElementById('email-error');
const passErr = document.getElementById('password-error');

function setError(input, errEl, message) {
    errEl.textContent = message;
    input.classList.add('invalid');
    input.setAttribute('aria-invalid', 'true');
}

function clearError(input, errEl) {
    errEl.textContent = '';
    input.classList.remove('invalid');
    input.removeAttribute('aria-invalid');
}

function validateEmail(value) {
    if (value.trim() === '') return 'البريد الإلكتروني مطلوب.';
    const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!re.test(value)) return 'صيغة البريد الإلكتروني غير صحيحة.';
    return '';
}

function validatePassword(value) {
    if (value.length === 0) return 'كلمة المرور مطلوبة.';
    if (value.length < 8) return 'كلمة المرور يجب أن تكون 8 أحرف على الأقل.';
    return '';
}

form.addEventListener('submit', (e) => {
    e.preventDefault();

    let ok = true;

    const emailMsg = validateEmail(email.value);
    if (emailMsg) { setError(email, emailErr, emailMsg); ok = false; }
    else { clearError(email, emailErr); }

    const passMsg = validatePassword(password.value);
    if (passMsg) { setError(password, passErr, passMsg); ok = false; }
    else { clearError(password, passErr); }

    if (!ok) {
        email.focus();
        return;
    }

    console.log('جاهز للإرسال:', {
        email: email.value,
        password: password.value
    });

    // لاحقاً:
    // fetch('/register', { method: 'POST', body: new FormData(form) });
});
معيار الإنجاز: لا إعادة تحميل عند الإرسال، رسائل خطأ عربية واضحة مرتبطة بالحقول، كل حقل له <small role="alert">، زر إرسال لا يُرسل إلا عند صحّة البيانات، والفشل لا يترك مستخدماً في حيرة.

أخطاء شائعة ونصائح

نسيان e.preventDefault

النموذج يُرسل، الصفحة تُعيد التحميل، وكل رسائل الخطأ تختفي مباشرة. الحل: أول سطر في معالج submit.

null عند السكربت المبكر

querySelector يعيد null إذا كان DOM لم يُبنَ بعد. الحل: defer أو نهاية body، والتحقق من النتيجة قبل الوصول لخصائصها.

innerHTML مع نص المستخدم

إدراج نص مستخدم في innerHTML يفتح ثغرة XSS. استخدم textContent للنصوص دائماً.

الاعتماد على onclick

element.onclick = fn يستبدل المستمع السابق. إذا ربطت مستمعين، يتجاهل المتصفح كل ما قبل الأخير. استخدم addEventListener.

إخفاء مؤشر التركيز

إزالة outline مع :focus يدمر الوصولية. لا تخفِ مؤشر التركيز أبداً. إن أردت جمالاً، استبدله بتصميم أوضح.

مقارنة القيمة بـ==

مدخلات النماذج نصوص دائماً. input.value == 0 تعمل بشكل مضلل. استخدم تحويلاً صريحاً: Number(value) === 0.

إعادة التحقق داخل كل ضغطة

التحقق فور كل حرف مزعج للمستخدم الذي لم يُكمل بعد. تحقق عند submit أو blur أفضل. input لتحقق خفيف فقط (مثل عدّاد الأحرف).

الاعتقاد أن تحقق الواجهة أمان

يمكن تجاوزه بسهولة. كرر التحقق في الخادم (Flask). اعتبره تحسيناً للتجربة، لا خط دفاع أمنياً.

نصائح ذهبية:
• ضع كل مستمعات الأحداث في نهاية الملف أو داخل DOMContentLoaded.
• احتفظ بمراجع العناصر في متغيرات ثابتة (const) لتجنّب البحث المتكرر.
• استخدم console.log أولاً، وأزله قبل التسليم.
• اقرأ event.target لتعرف مصدر الحدث.
• اختبر دائماً بلوحة المفاتيح، لا بالفأرة فقط.

ملخص المحاضرة

  • DOM هو تمثيل شجري للصفحة يبنيه المتصفح من HTML.
  • document هو الجذر، وكل وسم يصبح عنصراً له خصائص وأبناء.
  • الاختيار: getElementById للأيديهات، وquerySelector وquerySelectorAll للمحددات.
  • التعديل: textContent للنصوص الآمنة، innerHTML لحذر شديد.
  • classList.add/remove/toggle/contains هو أسلوبك للتفاعل.
  • الأحداث: addEventListener مع click، submit، input، blur.
  • e.preventDefault() ضروري لمنع الإرسال الافتراضي.
  • التحقق من الواجهة يحسّن التجربة، لكن التحقق الحقيقي في الخادم.
  • رسائل خطأ جيدة: واضحة، بالعربية، مرتبطة بالحقل، مع role="alert" وaria-invalid.
  • ضع السكربت في نهاية body أو مع defer لتفادي أخطاء null.

تقييم سريع

1) ما هو DOM ولماذا نحتاجه؟

DOM هو تمثيل برمجي للصفحة على شكل شجرة من الكائنات يبنيه المتصفح من HTML. نحتاجه لأن JavaScript لا تتعامل مع النص الخام، بل مع هذا النموذج. أي تعديل على DOM ينعكس مباشرة على الصفحة المرئية.

2) ما الفرق بين textContent وinnerHTML؟

textContent يعامل المحتوى كنص خام ولا يفسّر الوسوم. آمَن من XSS. innerHTML يفسّر الوسوم وينشئ عناصر، لذا خطر إذا كان المصدر نصاً من المستخدم.

3) ما وظيفة e.preventDefault() في معالج submit؟

يمنع السلوك الافتراضي للمتصفح، وهو إرسال النموذج إلى الخادم (أو إعادة تحميل الصفحة). بدونها تفقد أي تحقق مخصص تقوم به، وكل رسائل الخطأ تختفي.

4) ما معنى Cannot read properties of null وكيف نتفاداه؟

يعني أن querySelector لم يجد العنصر (أعطى null)، ثم حاول الكود الوصول لخاصية عليه. السبب: تشغيل السكربت قبل بناء DOM. الحل: defer أو نهاية body، أو التحقق من النتيجة.

5) لماذا نقول "التحقق من الواجهة الأمامية ليس أماناً"؟

لأنه يمكن تجاوزه بسهولة: تعطيل JavaScript، أدوات المطور، أو إرسال طلب مباشر بـcurl. التحقق الحقيقي يجب أن يكون في الخادم (Flask). ما في الواجهة هو تحسين للتجربة فقط.
