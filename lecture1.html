الإنترنت مقابل الويب

كثيراً ما نستخدم الكلمتين بالتبادل، لكنهما ليستا الشيء نفسه. الإنترنت هو البنية التحتية: شبكة عالمية ضخمة من الشبكات والأجهزة والكابلات وبروتوكولات الاتصال. أما الويب فهو خدمة تعمل فوق الإنترنت، تعتمد على بروتوكول HTTP/HTTPS ولغة HTML والروابط التشعبية.

الإنترنت

  • شبكة من الشبكات تربط الأجهزة عالمياً
  • تعتمد على بروتوكولات مثل TCP/IP
  • يشمل خدمات كثيرة: البريد، النقل، الويب
  • ليس خدمة واحدة فقط

الويب

  • خدمة تعمل فوق الإنترنت
  • تعتمد على HTTP/HTTPS وHTML
  • المتصفح هو بوابة المستخدم إليها
  • الصفحات والمواقع والتطبيقات الويب
معلومة مهمة: عندما تكتب عنواناً في المتصفح، فأنت غالباً تطلب مورداً عبر الويب. لكن الإنترنت نفسه كان موجوداً قبل الويب، وما زال يخدم تطبيقات أخرى مثل البريد الإلكتروني ونقل الملفات.

من الجهات المهمة التي تحافظ على معايير الويب: W3C وWHATWG، ومن أفضل المراجع اليومية للمطورين: MDN Web Docs. سنستخدم MDN كمرجع رسمي طوال المساق.

نموذج العميل–الخادم

الويب يقوم على علاقة أساسية: العميل يطلب، والخادم يستجيب. العميل هنا غالباً هو المتصفح، والخادم هو جهاز أو خدمة تعمل باستمرار وتستمع للطلبات. هذا النموذج هو حجر الأساس لفهم أي تطبيق ويب لاحقاً.

العميل (Client)

المتصفح يرسل الطلب، يعرض الصفحة، وينفّذ JavaScript.

طلب HTTP استجابة HTTP

الخادم (Server)

يستقبل الطلب، ينفّذ المنطق، ويرجع HTML أو JSON أو ملفات.

مسؤوليات العميل

  • إرسال طلبات HTTP إلى الخادم
  • عرض HTML وCSS
  • تنفيذ JavaScript داخل المتصفح
  • إدارة الجلسات والتخزين المحلي

مسؤوليات الخادم

  • الاستماع للطلبات على منفذ محدد
  • معالجة المسارات والمنطق البرمجي
  • الاتصال بقواعد البيانات
  • إرجاع الاستجابة بالصيغة المناسبة

عندما تفتح موقعاً، المتصفح لا يرى “الخادم” مباشرة. هو يرى عنواناً مثل https://example.com/courses/web، ثم يترجم هذا العنوان إلى طلب HTTP. عنوان URL يتكون عادة من: البروتوكول، اسم النطاق، المنفذ، المسار، وربما معاملات الاستعلام أو جزء #fragment.

الواجهة الأمامية والخلفية

تطبيق الويب الحديث ينقسم عادة إلى جزأين متكاملين. الواجهة الأمامية هي ما يراه المستخدم ويتفاعل معه داخل المتصفح. الواجهة الخلفية هي المنطق الذي يعمل على الخادم: المسارات، التحقق، المصادقة، قواعد البيانات، والأمان.

المحور الواجهة الأمامية الواجهة الخلفية
مكان التنفيذ متصفح المستخدم الخادم
التقنيات HTML · CSS · JavaScript Python · Flask · قواعد بيانات

الربط بينهما: في هذا المساق سنبدأ ببناء الواجهة الأمامية، ثم ننتقل لاحقاً إلى Python وFlask لبناء الواجهة الخلفية، ونجمع بينهما في مشروع متكامل.

دورة حياة طلب الويب وHTTP

لفهم ما يحدث عند فتح صفحة، تتبّع الرحلة التالية. هذه الرحلة تتكرر مع كل مورد: صفحة HTML، ملف CSS، صورة، أو طلب بيانات.

  1. المستخدم يكتب عنوان URL في المتصفح.
  2. المتصفح يستخدم DNS لتحويل اسم النطاق إلى عنوان IP للخادم.
  3. يتم إنشاء اتصال شبكي مع الخادم، وغالباً يكون مشفراً عبر HTTPS.
  4. المتصفح يرسل طلب HTTP، مثل GET /index.html HTTP/1.1.
  5. الخادم يستقبل الطلب، يحدد المسار المناسب، وينفّذ المنطق المطلوب.
  6. الخادم يرسل استجابة HTTP تتضمن رمز الحالة والترويسات والمحتوى.
  7. المتصفح يقرأ HTML، يبني DOM، يطبق CSS، ينفّذ JavaScript، ثم يعرض الصفحة.

طلب HTTP

  • GET: جلب مورد
  • POST: إرسال بيانات
  • يحتوي على مسار وترويسات وربما جسم
  • المتصفح يرسله نيابة عن المستخدم

استجابة HTTP

  • رمز الحالة: 200، 404، 500 …
  • ترويسات مثل Content-Type
  • جسم الاستجابة: HTML أو JSON أو ملف
  • المتصفح يقرر كيف يعرضها

من رموز الحالة المهمة: 200 OK للنجاح، 301/302 لإعادة التوجيه، 404 Not Found لعدم وجود المورد، 500 Internal Server Error لخطأ في الخادم. معرفة هذه الرموز ستساعدك كثيراً في التصحيح لاحقاً.

أول ملف HTML

الآن ننتقل إلى التطبيق. أنشئ مجلد web-course، افتحه في VS Code، ثم أنشئ ملفاً باسم index.html. اكتب الكود التالي، واحفظ الملف بترميز UTF-8.

index.html HTML 
<!DOCTYPE html>
<html lang="ar" dir="rtl">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>صفحتي الأولى</title>
</head>
<body>
    <h1>مرحباً، أنا طالب في مساق الويب</h1>
    <p>هذه أول صفحة HTML أنشئها داخل المساق.</p>

    <h2>مهاراتي الحالية</h2>
    <ul>
        <li>استخدام VS Code</li>
        <li>كتابة HTML أساسي</li>
        <li>فحص الصفحة بأدوات المطور</li>
    </ul>

    <p>
        <a href="https://developer.mozilla.org/ar/" target="_blank" rel="noopener noreferrer">
            زيارة توثيق MDN
        </a>
    </p>
</body>
</html>

بنية المستند

  • <!DOCTYPE html> يحدد HTML5
  • <html> جذر المستند
  • <head> بيانات وصفية
  • <body> المحتوى المرئي

اللغة والاتجاه

  • lang="ar" لغة المحتوى
  • dir="rtl" اتجاه من اليمين لليسار
  • charset="UTF-8" لدعم العربية
  • viewport لتحسين العرض على الهاتف

بعد الحفظ، افتح الملف في المتصفح. يمكنك النقر المزدوج عليه، أو استخدام إضافة Live Server في VS Code. لاحظ أن فتح الملف مباشرة يعطي عنواناً يبدأ بـ file://، بينما Live Server يعطيك عنواناً يبدأ بـ http://، وهو أقرب لبيئة الويب الحقيقية.

أدوات المطور وDOM

أدوات المطور هي معملك الحقيقي في المتصفح. افتحها بالضغط على F12 أو Ctrl + Shift + I. سنستخدم الآن تبويب Elements لفحص شجرة DOM، وتبويب Console لتجربة أوامر سريعة.

Elements

  • يعرض شجرة DOM الحالية
  • يمكنك تحديد أي عنصر وفحص خصائصه
  • تعديل مؤقت للتجربة فقط
  • لا يحفظ التغييرات في الملف الأصلي

Console

  • تشغيل JavaScript مباشرة
  • قراءة الأخطاء والتحذيرات
  • تجربة document.querySelector
  • طباعة قيم للفحص السريع

Network

  • عرض الطلبات التي أرسلها المتصفح
  • حالة كل طلب: 200، 404، 500
  • حجم الملفات وزمن التحميل
  • مفيد لتصحيح CSS والصور

جرّب في تبويب Console كتابة الأمر التالي لتغيير نص العنوان مؤقتاً:

Console JS 
document.querySelector('h1').textContent = 'تم التغيير من Console';
مهم: التغيير من تبويب Elements أو Console هو تغيير مؤقت في نسخة المتصفح فقط. إذا أعدت تحميل الصفحة، سيعود المحتوى كما هو مكتوب في ملف index.html. التعديل الدائم يكون دائماً في ملفات المشروع.

التطبيق العملي

نفّذ الخطوات التالية داخل مجلد web-course، ثم جهّز المخرجات للتسليم.

تطبيق المحاضرة 1

  1. أنشئ مجلد web-course وافتحه في VS Code.
  2. أنشئ ملف index.html يحتوي على:
    • عنوان h1 باسمك.
    • فقرة تعريفية قصيرة عنك.
    • قائمة ul بثلاث مهارات أو تقنيات تحبها.
    • رابط خارجي إلى MDN مع target="_blank" وrel="noopener noreferrer".
  3. افتح الصفحة في المتصفح، أو شغّلها عبر Live Server.
  4. افتح أدوات المطور، وافحص العنصر h1 من تبويب Elements.
  5. من تبويب Console، غيّر نص h1 مؤقتاً، ثم أعد تحميل الصفحة ولاحظ عودة النص الأصلي.
  6. من تبويب Network، أعد تحميل الصفحة وتحقق من حالة طلب index.html.
  7. التقط صورة للصفحة وصورة لتبويب Elements، وأرفقهما مع ملف index.html.
معيار الإنجاز: صفحة تعمل، نص عربي يظهر بشكل صحيح، رابط خارجي يعمل، وشجرة DOM ظاهرة في أدوات المطور.

أخطاء شائعة ونصائح

نسيان charset

إذا ظهرت الحروف العربية كرموز غريبة، تأكد من وجود <meta charset="UTF-8"> داخل head.

نسيان viewport

بدون viewport، ستبدو الصفحة مصغّرة على الهاتف. استخدم وسم meta name="viewport" دائماً.

مسار ملف خاطئ

إذا لم يظهر ملف CSS أو صورة، تحقق من المسار النسبي، ومن اسم الملف وحالة الأحرف، ومن وجود الملف فعلاً في المجلد.

تعديل غير محفوظ

في VS Code، إذا لم تحفظ الملف Ctrl + S، فلن ترى التغيير في المتصفح. تحقق من نقطة الحفظ بجانب اسم الملف.

ملخص المحاضرة

  • الإنترنت هو البنية التحتية، والويب خدمة تعمل فوقه عبر HTTP/HTTPS.
  • نموذج العميل–الخادم: المتصفح يرسل طلباً، والخادم يرد باستجابة.
  • الواجهة الأمامية تُنفّذ في المتصفح بـ HTML وCSS وJavaScript.
  • الواجهة الخلفية تُنفّذ على الخادم، وستبنى لاحقاً بـ Python وFlask.
  • دورة الطلب تشمل DNS، اتصال الشبكة، طلب HTTP، استجابة، ثم عرض الصفحة.
  • جهّزنا VS Code ومجلد مشروع، وأنشأنا أول ملف HTML5.
  • أدوات المطور تساعدنا في فحص DOM والشبكة وتجربة JavaScript.

تقييم سريع

1) ما الفرق بين الإنترنت والويب؟

الإنترنت هو الشبكة العالمية للأجهزة والاتصالات، أما الويب فهو خدمة تعمل فوق الإنترنت وتستخدم HTTP/HTTPS وHTML لعرض الصفحات والمواقع.

2) من هو العميل ومن هو الخادم في طلب ويب عادي؟

العميل هو المتصفح الذي يرسل الطلب، والخادم هو الجهاز أو الخدمة التي تستقبل الطلب وتعيد الاستجابة.

3) ماذا يفعل المتصفح بعد استلام ملف HTML؟

يبني شجرة DOM، ويطبق CSS، وينفّذ JavaScript، ثم يرسم الصفحة للمستخدم.

4) ما وظيفة تبويب Elements في أدوات المطور؟

يعرض شجرة DOM الحالية للصفحة، ويسمح بفحص العناصر وتجربة تعديلات مؤقتة لا تُحفظ في الملف الأصلي.

5) لماذا نستخدم charset="UTF-8"؟

لدعم عرض الحروف العربية واللغات الأخرى بشكل صحيح، وتجنب ظهور النص كرموز غير مفهومة.
