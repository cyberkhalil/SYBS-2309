[03:00 – 10:00] ما هي JavaScript ولماذا نتعلمها
============================================================

JavaScript هي لغة البرمجة الأساسية في الويب.
هي اللغة التي تجعل الصفحة تتفاعل.

HTML تبني العناصر، لكنها لا تتكلم. لا تحسب مجموعاً،
ولا تتحقق من بريد، ولا تتفاعل مع نقرة زر.
CSS تُنسّق الشكل فقط، وتستطيع أن تُظهر تأثير hover،
لكنها لا تنفّذ منطقاً.

JavaScript هي التي تنفّذ المنطق.
تقول: "عندما ينقر المستخدم على الزر، احسب المجموع،
تحقّق من صحة الإدخال، وأظهر رسالة الخطأ".
هذه كلها مهام JavaScript.

في هذا المساق سنستخدمها في:
- التحقق من النماذج في الواجهة الأمامية.
- التلاعب بالمحتوى على الصفحة.
- الاستجابة للأحداث: نقر، إدخال، إرسال نموذج.
- التواصل مع الخادم لاحقاً عند دراستنا لـ Flask.

ودّي أذكّر بشيء يخلط فيه المبتدئون:
JavaScript ليست Java. الاسم متشابه فقط لأسباب تسويقية تاريخية.
اللغتان مختلفتان تماماً.

كيف تعمل JavaScript في المتصفح؟
كل متصفح حديث فيه محرّك JavaScript.
كروم فيه V8، فايرفوكس فيه SpiderMonkey، سفاري فيه JavaScriptCore.
هذا المحرّك يقرأ كود JS وينفّذه داخل المتصفح.

ولأنها تعمل في المتصفح، تستطيع JavaScript الوصول إلى DOCUMENT
OBJECT MODEL، أي DOM. وبذلك تعدّل الصفحة، تضيف عناصر، تغيّر النصوص،
تربط أحداثاً. سنتعلم هذا في المحاضرة القادمة إن شاء الله.

[10:00 – 20:00] إضافة JavaScript إلى HTML
============================================================

كيف نضيف JavaScript إلى صفحة HTML؟

عندنا ثلاث طرق، تماماً كما في CSS.

الطريقة الأولى: inline — ضمني.
داخل السمات مثل onclick أو onchange.
مثال:
<button onclick="alert('مرحباً')">اضغط</button>

هذه الطريقة تعمل، لكنها سيئة. لماذا؟
لأنها تخلط البنية بالسلوك، ولا تُعاد استخدامها،
وصعبة الصيانة. لا نستخدمها إلا للتوضيح.

الطريقة الثانية: internal — داخلي.
داخل وسم script في الصفحة:
<script>
    console.log('هذا سكربت داخلي');
</script>

هذه أفضل من الطريقة الأولى، لكنها لا تُخزَّن مؤقتاً
ولا تُعاد استخدامها بين الصفحات. مقبولة لصفحة واحدة،
لكن الأفضل هو الخيار الثالث.

الطريقة الثالثة: external — خارجي.
ملف .js منفصل، يُربط عبر:
<script src="main.js"></script>

هذا أفضل شيء. لماذا؟
لأن الملف نفسه يُستخدم في كل الصفحات.
يُخزَّن مؤقتاً في المتصفح فلا يُعاد تنزيله.
سهل الصيانة: تغيّر مكاناً واحداً فينعكس على كل الصفحات.
وهذا ما سنستخدمه في المساق.

الآن أين نضع وسم script؟

هناك سؤال مهم جداً: أين نضع <script> في HTML؟

الخيار الأول: في نهاية body.
هذا آمن لأن كل العناصر التي قد يستخدمها السكربت
قد تم بناؤها بالفعل.

الخيار الثاني: في head مع defer.
<script src="main.js" defer></script>
كلمة defer تعني: نزّل الملف بالتوازي مع بناء الصفحة،
لكن نفّذه فقط بعد الانتهاء من بناء DOM كاملاً.

لماذا هذا مهم؟
إذا وضعت السكربت في head بدون defer، فقد ينفّذ قبل
وجود العناصر. ثم يحاول الوصول إلى عنصر لم يُبنَ بعد،
فتظهر رسالة:
"Cannot read property of null".

هذا خطأ شائع جداً عند المبتدئين.
القاعدة: نهاية body، أو head مع defer.

الفرق بين defer وasync؟
defer يحافظ على ترتيب تنفيذ السكربتات، وينفّذ بعد بناء DOM.
async ينفّذ بمجرد تحميل الملف، وقد يغيّر الترتيب.
في المساق نستخدم defer دائماً.

[20:00 – 35:00] المتغيرات: let و const
============================================================

الآن نأتي إلى قلب البرمجة: المتغيرات.

المتغير هو اسم مرتبط بقيمة. بدونه، لا يمكن أن تحتفظ
ببيانات وتعيد استخدامها. تخيل أنك تحسب مجموع درجات،
وتريد استخدام الناتج في مكان آخر. ولا بد من متغير يحمله.

في JavaScript الحديثة، عندنا ثلاث كلمات لتعريف المتغيرات:
var، let، وconst.

var قديمة، ولها مشاكل سلوكية في النطاق (scope). نتجنبها
في المشاريع الحديثة، ولن نستخدمها في المساق.

let هي للمتغيرات القابلة للتعديل.
const للقيم الثابتة التي لا تُعاد تعيينها.

مثال:

const TAX_RATE = 0.05;
const APP_NAME = 'حاسبة البقشيش';

let count = 0;
let tip = 0;

count = count + 1;
tip = 25;

هنا استخدمنا const للقيم الثابتة، وlet للقيم المتغيرة.
لو حاولت:
TAX_RATE = 0.10;
ستحصل على TypeError.

متى نستخدم let ومتى const؟
القاعدة الحديثة واضحة: const افتراضياً. لا تستخدم let
إلا إذا كنت تعرف أن القيمة ستتغير فعلاً.

لماذا؟ لأنك حين تقرأ الكود بعد شهر، تعرف فوراً أي قيم
يُتوقع تعديلها. وconst تحمي من الأخطاء غير المقصودة.

ملاحظات على أسماء المتغيرات:
استخدم camelCase: userName, finalTotal, isSubscribed.
لا تستخدم أسماء عربية بحروف غير لاتينية، رغم أن JS تقبلها،
لأنها تسبب صداعاً في التبديل بين اللغات والمسارات.
لا تبدأ الأسماء برقم.
لا تستخدم كلمات محجوزة مثل if أو for أو let.
اجعل الاسم وصفياً: بدل x نكتب maybeTotal.

[35:00 – 50:00] أنواع البيانات
============================================================

JavaScript لغة ذات أنواع ديناميكية. يعني المتغير يمكنه
أن يحمل نوعاً، ثم يحمل نوعاً آخر لاحقاً. هذا مرن، لكنه
يحتاج حذراً.

الأنواع الأساسية التي سنستخدمها:

أولاً: string — النصوص.
بين علامات مفردة 'مرحباً'، أو مزدوجة "مرحباً"،
أو backticks `مرحباً`.

ثانياً: number — الأرقام.
لا يوجد فرق بين عدد صحيح وعدد عشري في JS.
كلاهما number. مثل 42، 3.14، -7.

ثالثاً: boolean — القيم المنطقية.
true أو false فقط. لا شيء بينهما.

رابعاً: undefined.
حين تُعرّف متغيراً بلا قيمة:
let x;
x هو undefined.

خامساً: null.
قيمة فارغة متعمدة، تأتي من صاحب الكود لا من JS.
مثلاً: ملف المستخدم لم يُرفع بعد، نضع null.

سادساً: array.
قائمة مرتبة. [1, 2, 3] أو ['HTML', 'CSS', 'JS'].

سابعاً: object.
كائن بخصائص. { name: 'سارة', age: 20 }.
سنتعلمه لاحقاً، يكفينا الآن أن نعرف شكله.

كيف نتحقق من النوع؟
باستخدام typeof:

typeof 'سارة'    → "string"
typeof 42        → "number"
typeof true      → "boolean"
typeof undefined → "undefined"
typeof null      → "object"   (سلوك تاريخي غريب)
typeof [1,2,3]   → "object"

انتبهوا لـ null: typeof يعطي "object". هذا سلوك لغوي
تاريخي وليس خطأ نحوي. للتحقق من null نستخدم === null.

التحويل بين الأنواع:
Number('14')     → 14
parseInt('14px') → 14
String(14)       → "14"
(14).toString()  → "14"

لكن انتبهوا:
Number('abc') → NaN
NaN تعني Not a Number، وهي مؤشر على إدخال غير صالح.
في نماذج المستخدم، تحقق من NaN قبل استخدام الرقم.

[50:00 – 65:00] العمليات الحسابية والمقارنة والمنطقية
============================================================

الآن العمليات. هذه العصب الأساسي لكل شروطك وقراراتك.

العمليات الحسابية:
+ للجمع
- للطرح
* للضرب
/ للقسمة
% لباقي القسمة
** للأس

مثال:
const a = 10;
const b = 3;

a + b   → 13
a - b   → 7
a * b   → 30
a / b   → 3.3333…
a % b   → 1
a ** b  → 1000

العمليات المقارنة:
=== يساوي (قيمة ونوع)
!== لا يساوي (قيمة ونوع)
> أكبر
< أصغر
>= أكبر أو يساوي
<= أصغر أو يساوي
== يساوي (بعد تحويل النوع) — نتجنبها

أهم ملاحظة هنا: استخدم === دائماً، لا ==.
السبب: '5' == 5 ترجع true بسبب تحويل النوع التلقائي.
أما '5' === 5 فترجع false لأن النوعين مختلفان.
هذا الفرق ينتج أخطاء منطقية غامضة في الشروط،
ويسبب ساعات من الحيرة. تعلّم من البداية استخدام ===.

العمليات المنطقية:
&& و — تحتاج كلا الطرفين صحيحاً
|| أو — يكفي أحدهما صحيحاً
! ليس — عكس القيمة

مثال:
const isAdult = true;
const hasTicket = false;

isAdult && hasTicket  → false
isAdult || hasTicket  → true
!isAdult              → false

تحذير مهم على +:
في JavaScript، + لها وظيفتان:
- جمع الأرقام: 5 + 3 = 8
- دمج النصوص: '5' + 3 = '53'

هذا مصدر أخطاء متكرر عند التعامل مع مدخلات النماذج،
لأنها تأتي دائماً كنصوص. حلّل النص إلى رقم أولاً:
Number(input.value) + 5

[65:00 – 75:00] Template literals
============================================================

قبل أن ندخل في المصفوفات، نتكلم عن شيء يوفّر وقتاً كبيراً:
Template literals.

قديماً كنا نكتب:
'مرحباً ' + name + '، عمرك ' + age + ' سنة'

هذا مزعج، ويكثر فيه الأخطاء بسبب علامات الاقتباس
والفواصل والمسافات.

الآن نكتب:
`مرحباً ${name}، عمرك ${age} سنة`

Backticks — وليس علامات اقتباس عادية.
بین ${ } نضع تعبيراً، لا مجرد متغير. يمكن أن يكون
حسابياً: ${10 + 5} يطبع 15.

مزايا Template literals:
- دمج نصوص أنظف
- دعم الأسطر المتعددة تلقائياً
- إدراج تعبيرات، لا مجرد متغيرات

مثال على أسطر متعددة:
const msg = `السطر الأول
السطر الثاني
السطر الثالث`;
هذا يعمل بدون \n يدوياً.

هذا مفيد جداً لبناء HTML داخل JavaScript:
const card = `<article class="card"><h2>${name}</h2></article>`;
سنتعلم إدراجه في DOM لاحقاً.

انتبهوا: backticks ليست على زر علامات الاقتباس العادي.
عادة تكون تحت زر Esc في لوحة المفاتيح، مع زر ~.
ملاحظة عملية: خذ دقيقة لتجدها، لأنك ستحتاجها كثيراً.

[75:00 – 85:00] المصفوفات
============================================================

المصفوفة array هي قائمة مرتبة من القيم.

const skills = ['HTML', 'CSS', 'JavaScript'];
const numbers = [10, 20, 30, 40];

العناصر تُفهرَس من 0، لا من 1.
skills[0] → HTML
skills[2] → JavaScript

الطول: skills.length → 3

آخر عنصر: skills[skills.length - 1] → JavaScript

لماذا length - 1؟ لأن الفهرسة تبدأ من 0، والعدد 3 يعني
أن الفهارس 0, 1, 2. آخر فهرس = 2 = 3 - 1.

إضافة وحذف:
skills.push('Python')     → يضيف في الأخير
skills.pop()              → يحذف من الأخير
skills.unshift('Python')  → يضيف في الأول
skills.shift()            → يحذف من الأول

ملاحظة على const والمصفوفات:
const skills = [...] تعني أن المرجع ثابت، لا أن المحتوى
ثابت. يمكنك push وpop لأنك تعدّل المحتوى، لكن لا يمكنك
إعادة التعيين: skills = []; خطأ.

هذا مبدأ مهم في JS:
const تمنع إعادة التعيين، لا تمنع التعديل.
في المحاضرة القادمة سنرى map وfilter وforEach، وهي أدوات
أقوى للمرور على المصفوفات.

[85:00 – 95:00] Console وتصحيح الأخطاء
============================================================

Console هو أفضل صديق لك.

افتحه بـ F12، ثم تبويب Console.
هناك تكتب أي تعبير JS وينفّذ فوراً.

الأهم: console.log للطباعة.

أمثلة:
console.log('مرحباً');
console.log('الاسم:', name, '— العمر:', age);
console.log(`الاسم ${name}`);

هناك اختصارات أخرى مفيدة:
console.info للنقل معلومات
console.warn للتحذير
console.error للخطأ
console.table للمصفوفات والكائنات — يعرض جدولاً جميلاً
console.time / timeEnd لقياس زمن عملية

تحدثنا كثيراً عن console.log، فلماذا؟
لأنه أداة التصحيح الأولى.
عندما لا يعمل الكود، أول سؤال تسأله:
"هل طبعت القيم فعلاً؟".

مثال: لديك:
const bill = 120;
const tipPercent = 15;
const total = bill + tipPercent;

تتوقع 138، لكن تحصل على 135؟ اطبع:
console.log(bill, tipPercent);
تكتشف أن tipPercent = 15، والناتج 135 صحيح، لكن
يجب أن تحسب النسبة: bill * tipPercent / 100.
الطباعة كشفت الخطأ.

أنواع الأخطاء التي ستراها:

SyntaxError: خطأ كتابي. نسيت قوساً، أو فاصلة، أو
استخدمت كلمة محجوزة.

ReferenceError: حاولت استخدام متغير غير معرّف.
مثل: console.log(x); بدون let x.

TypeError: نوع القيمة غير مناسب للعملية.
مثل: null.name — لا يمكن قراءة خاصية من null.

RangeError: قيمة خارج النطاق.
مثل: new Array(-1) — طول سالب.

عادات جيدة:
- اطبع القيمة قبل استخدامها.
- اقرأ الخطأ حرفياً، لا تخمّن.
- علّق أجزاءً لتحديد مصدر الخطأ.
- استخدم typeof عند الشك في النوع.
- احذف console.log قبل التسليم — يُترك للتصحيح فقط.

[118:00 – 126:00] أخطاء شائعة ونصائح
============================================================

دعونا نمرّ على أخطاء شائعة، لأن التعرف عليها الآن
يوفّر عليكم ساعات لاحقاً.

أولاً: استخدام == بدل ===.
كثيراً ما تكون النتائج غير متوقعة، وخاصة مع النصوص
التي تأتي من النماذج.

ثانياً: خلط علامات النصوص.
البدء بـ ' والإنهاء بـ " يعطي SyntaxError.
التزم بنفس العلامة في الطرفين.

ثالثاً: نسيان backticks.
محاولة استخدام ${} داخل علامات اقتباس عادية
لا تعمل. ${} تحتاج backticks.
مثال:
'مرحباً ${name}' → لا تعمل
`مرحباً ${name}` → تعمل

رابعاً: جمع نص ورقم.
'10' + 5 يعطي '105'. حوّل النص إلى رقم:
Number('10') + 5 = 15.

خامساً: إعادة تعريف const.
const x = 5; x = 10; خطأ. استخدم let إذا كنت تنوي التعديل.

سادساً: تشغيل السكربت قبل وجود DOM.
ضع السكربت في نهاية body أو استخدم defer.

سابعاً: نسيان الفاصلة المنقوطة.
JS في الغالب تتسامح، لكن هذا قد يُنتج أخطاء غامضة.
اكتب ; في نهاية كل جملة.

ثامناً: استخدام var في مشروع جديد.
استخدم let وconst فقط.

نصائح:
- اقرأ الخطأ في Console حرفياً.
- اطبع القيم قبل استخدامها.
- استخدم أسماء معبّرة.
- قسّم السكربت إلى أقسام بتعليقات.
- احذف console.log قبل التسليم.

[126:00 – 130:00] الملخص والواجب والخاتمة
============================================================

نلخص المحاضرة:

- JavaScript تضيف السلوك للصفحة.
- نضيفها عبر external (الأفضل) أو internal أو inline.
- نضع السكربت في نهاية body أو head مع defer.
- let وconst للمتغيرات، وconst افتراضياً.
- الأنواع الأساسية: string, number, boolean, array, undefined, null.
- العمليات الحسابية والمقارنة (=== دائماً) والمنطقية.
- Template literals بـ`...${expr}...` لأنظف نصوص.
- المصفوفات تُفهرَس من 0، وتدعم push وpop.length.
- console.log سلاحك الأول للتصحيح.
- اقرأ أنواع الأخطاء: SyntaxError، ReferenceError، TypeError.

الواجب:
تسليم lab6.js كاملاً مع السكربتات الثلاثة،
وصورة من Console تعرض المخرجات.
تحقق من:
- النتائج صحيحة.
- لا أخطاء حمراء في التنفيذ العادي.
- استخدام const وlet بشكل صحيح.

في المحاضرة القادمة ننتقل إلى المنطق البرمجي والدوال:
الشروط if/else، switch، الحلقات for/while،
المصفوفات المتقدمة (map، filter)، ومعالجة الأخطاء try/catch.
