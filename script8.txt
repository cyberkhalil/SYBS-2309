[03:00 – 12:00] ما هو DOM؟
============================================================

DOM — اختصار Document Object Model — نموذج كائنات المستند.

تخيلوا معي: أنتم كتبتم ملف HTML، وفيه وسوم html، head،
body، h1، p، ul، li. هذا نص مكتوب في الملف.

المتصفح عندما يقرأ هذا الملف، لا يبقيه نصاً. هو يحوّله
إلى شجرة من الكائنات. كل وسم يصبح "كائناً" له خصائص
ويمكن التعامل معه.

هذه الشجرة هي DOM.

هذه نقطة في غاية الأهمية:
JavaScript لا تتعامل مع HTML كنص. تتعامل مع DOM.
حين تقول:
document.querySelector('h1')
أنت لا تقرأ الملف. أنت تبحث في الشجرة التي بناها المتصفح.

لماذا DOM مهم؟
لأن كل تعديل تفعله JavaScript على DOM ينعكس مباشرة
على الصفحة المرئية. تغيّر نص h1 في DOM، يتغير النص
أمام المستخدم فوراً. تضيف صنفاً، تظهر تأثيرات CSS.
تحذف عنصراً، يختفي من الشاشة.

لهذا كل التفاعل في الويب يمر عبر DOM.

دعونا نتخيل شكل الشجرة:

document
└── html
    ├── head
    │   ├── meta
    │   ├── title
    │   └── link
    └── body
        ├── header
        │   └── h1
        ├── main
        │   ├── p
        │   └── ul
        │       ├── li
        │       └── li
        └── footer

كل عنصر له أب وأبناء. html هو جذر المستند (بعد document).
head وbody أبناء له. كل ما في الصفحة أولادهم.

الآن، مهم جداً أن نفهم: متى يُبنى DOM؟
DOM يُبنى تدريجياً أثناء قراءة المتصفح لملف HTML.
ليس كاملاً من أول لحظة.

هذا مهم لأن سكربتنا قد يعمل قبل بناء DOM كاملاً.
ثم يحاول الوصول إلى عنصر لم يوجد بعد.
النتيجة: خطأ شائع جداً:
Cannot read properties of null.

هذا الخطأ سنراه كثيراً في البداية.
الحل بسيط:
1. ضع السكربت في نهاية body.
2. أو ضعه في head مع السمة defer.

هذا كل شيء. سنكرر هذه النقطة عدة مرات لأنها السبب
في كثير من الحيرة عند المبتدئين.

[12:00 – 25:00] اختيار العناصر
============================================================

كل عملية في DOM تبدأ بالاختيار. نحدد عنصراً موجوداً
في الصفحة، ثم نتعامل معه.

الأدوات الأساسية:

أولاً: getElementById.
const hero = document.getElementById('hero');
يبحث عن عنصر له id="hero".
هو سريع جداً، لأنه يستخدم فهرس داخلي.
لا يقبل محددات CSS، فقط id.

ثانياً: querySelector.
const card = document.querySelector('.card');
يقبل أي محدد CSS: صنف، وسم، سمة، حالات.
يعيد أول عنصر يطابق.
هذا هو الخيار اليومي.

ثالثاً: querySelectorAll.
const cards = document.querySelectorAll('.card');
يعيد كل العناصر المطابقة على شكل NodeList.
يمكن المرور عليها بـ forEach.
ملاحظة: NodeList ليس مصفوفة حقيقية.
إذا احتجت دوال المصفوفات مثل map، استخدم Array.from(cards).

رابعاً: getElementsByClassName و getElementsByTagName.
هذه أقدم. ترجع HTMLCollection حية، تتحدث تلقائياً
مع تغيير DOM. لهذا قد تُنتج مفاجآت.
نتجنبها في المشاريع الحديثة.

الآن، نقطة مهمة على null.
كل دوال البحث قد تعيد null إذا لم تجد العنصر.

const x = document.querySelector('.missing');
console.log(x);  // null

ثم:
x.textContent = 'hi';
// Cannot read properties of null

لهذا تحققوا قبل الاستخدام:
if (x) { x.textContent = 'hi'; }
أو استخدموا optional chaining:
x?.textContent = 'hi';

هذا أسلوب حديث ومختصر.

نصيحة عملية: احفظ مراجع العناصر في متغيرات const.
بدل:
document.querySelector('.btn').addEventListener(...)
document.querySelector('.btn').addEventListener(...)

اكتب:
const btn = document.querySelector('.btn');
btn.addEventListener(...)

هذا أسرع، وأنظف، ويقلل تكرار البحث.

[25:00 – 40:00] تعديل المحتوى والخصائص والأصناف
============================================================

بعد الاختيار، نعدّل. عندنا عدة أوجه:

1) المحتوى — textContent:
title.textContent = 'عنوان جديد';

هذا يضع النص حرفياً. أي وسوم HTML داخل النص
تُظهر كنص، لا تُفسَّر. مثلاً:
box.textContent = '<b>عريض</b>';
ستظهر النص "<b>عريض</b>" حرفياً على الشاشة.
هذا آمن، وهذا ما نريده في 90% من الحالات.

2) المحتوى — innerHTML:
box.innerHTML = '<b>عريض</b>';

هنا سترى كلمة "عريض" بخط عريض. الوسم فُسِّر.

لكن كن حذراً مع innerHTML:
إذا كنت تعرض نصاً من المستخدم (تعليق، اسم) ففيه خطر.
المستخدم قد يكتب:
<img src=x onerror="alert(1)">

هذا النص، إذا حُقن في innerHTML، سينفّذ alert!
هذه ثغرة XSS — Cross-Site Scripting.

القاعدة:
- للنصوص: textContent.
- لـ HTML تكتبه أنت: innerHTML مقبول.
- لنص من المستخدم: لا تستخدم innerHTML.

3) الخصائص — setAttribute:
link.setAttribute('href', 'https://example.com');
link.setAttribute('target', '_blank');
link.setAttribute('rel', 'noopener noreferrer');

أو مباشرة:
link.href = 'https://example.com';

كلتاهما تعمل. المباشر أسرع.
لكن مع بعض الخصائص المعقدة، تحتاج setAttribute.

4) الأصناف — classList:
هذه أهم أداة للتفاعل.

card.classList.add('active');        // إضافة
card.classList.remove('hidden');     // حذف
card.classList.toggle('dark');       // يضيف أو يحذف
card.classList.contains('active');   // يعيد true/false

لماذا classList أفضل من style؟
لأنك تفصل الشكل عن السلوك.
تضع كل تنسيقات "active" في CSS، وتضيفها بحذف الصنف.
هذا يجعل التصميم مستقلاً عن JavaScript.
لو غيّرت لون active لاحقاً، تغيّره في مكان واحد.

5) الأنماط — style:
card.style.color = '#3b82f6';

هذا يعمل، لكنه يخلط السلوك بالتصميم.
نستخدمه فقط عندما نريد قيمة محسوبة (مثل position
بناءً على موضع الفأرة). للأشياء العادية، استخدم classList.

[40:00 – 55:00] الأحداث
============================================================

الآن نأتي إلى جوهر التفاعل: الأحداث.

الحدث هو شيء يحدث. نقر زر، إرسال نموذج، كتابة حرف،
تمرير صفحة، تغيير حجم نافذة.

JavaScript تستمع لهذه الأحداث وتنفّذ كوداً.

الأداة الأساسية: addEventListener.

btn.addEventListener('click', () => {
    console.log('تم النقر');
});

هذا يربط مستمعاً بالحدث. عند كل نقرة، ينفّذ الدالة.

أهم الأحداث التي سنستخدمها:

click — نقر أو لمس.
submit — إرسال نموذج.
input — تغيّير قيمة حقل أثناء الكتابة (كل حرف).
change — تغيّر القيمة ثم مغادرة الحقل.
blur — خروج العنصر من التركيز.
focus — دخول التركيز.
keydown — ضغط مفتاح.

هناك كائن event يمرَّر تلقائياً لكل معالج.
داخله معلومات: المتحكمات، المفاتيح، وغيرها.

input.addEventListener('input', (e) => {
    console.log('القيمة:', e.target.value);
});

e.target هو العنصر الذي أطلق الحدث. في هذا المثال،
حقل الإدخال نفسه. e.target.value تعطي النص الحالي.

هناك دالة مهمة جداً: preventDefault.
form.addEventListener('submit', (e) => {
    e.preventDefault();
    // الكود هنا
});

ماذا تفعل preventDefault؟
تمنع السلوك الافتراضي للمتصفح.
عند submit، السلوك الافتراضي هو إرسال النموذج وإعادة
تحميل الصفحة. preventDefault تمنعه، فتبقى في نفس
الصفحة، وتستطيع تنفيذ تحققك، ثم إرسال البيانات
بطريقتك الخاصة.

هذه أول نقطة يقع فيها المبتدئون:
يكتبون تحققاً رائعاً، ثم يجرّبون، فتظهر الصفحة سريعاً
كأنها أعادت التحميل. السبب: نسيان preventDefault.

الآن، addEventListener مقابل onclick:
element.onclick = fn;

هذا يعمل، لكن له مشكلة: إذا ربطت مستمعاً ثانياً،
سيلغي الأول. addEventListener يضيف، لا يستبدل.

لذلك: لا تستخدم onclick في JavaScript الحديثة،
ولا تستخدم السمة onclick="" في HTML.
استخدم addEventListener دائماً.

[55:00 – 75:00] التحقق من النماذج في الواجهة الأمامية
============================================================

الآن نطبق كل ما تعلمناه في السيناريو الأشهر:
التحقق من نموذج تسجيل.

لماذا التحقق في الواجهة؟
ثلاثة أسباب:
1. تجربة أفضل: المستخدم يعرف خطأه فوراً، لا ينتظر الخادم.
2. تقليل الطلبات غير الصالحة.
3. رسائل عربية موحدة بدل رسائل المتصفح.

لكن — وهذه نقطة سنكررها دائماً:
التحقق في الواجهة ليس أماناً.
يمكن تعطيله أو تجاوزه.
التحقق الحقيقي في الخادم.
هنا نضيف طبقة أولى فقط.

دعونا نكتب الكود:

1. في HTML:

<form id="register-form" novalidate>
    <p>
        <label for="email">البريد الإلكتروني</label>
        <input type="email" id="email" name="email" required>
        <small class="error" id="email-error" role="alert"></small>
    </p>

    <p>
        <label for="password">كلمة المرور</label>
        <input type="password" id="password" name="password"
               required minlength="8">
        <small class="error" id="password-error" role="alert"></small>
    </p>

    <button type="submit">إنشاء الحساب</button>
</form>

ملاحظة: novalidate على form يعطّل رسائل المتصفح الافتراضية.
بهذا نحن نتحكم بالتجربة بالكامل.

2. في JavaScript:

const form = document.getElementById('register-form');
const email = document.getElementById('email');
const password = document.getElementById('password');
const emailErr = document.getElementById('email-error');
const passErr = document.getElementById('password-error');

function setError(input, errEl, message) {
    errEl.textContent = message;
    input.classList.add('invalid');
    input.setAttribute('aria-invalid', 'true');
}

function clearError(input, errEl) {
    errEl.textContent = '';
    input.classList.remove('invalid');
    input.removeAttribute('aria-invalid');
}

function validateEmail(value) {
    if (value.trim() === '') return 'البريد الإلكتروني مطلوب.';
    const re = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!re.test(value)) return 'صيغة البريد غير صحيحة.';
    return '';
}

function validatePassword(value) {
    if (value.length === 0) return 'كلمة المرور مطلوبة.';
    if (value.length < 8) return 'كلمة المرور يجب أن تكون 8 أحرف أو أكثر.';
    return '';
}

form.addEventListener('submit', (e) => {
    e.preventDefault();

    let ok = true;

    const emailMsg = validateEmail(email.value);
    if (emailMsg) { setError(email, emailErr, emailMsg); ok = false; }
    else { clearError(email, emailErr); }

    const passMsg = validatePassword(password.value);
    if (passMsg) { setError(password, passErr, passMsg); ok = false; }
    else { clearError(password, passErr); }

    if (!ok) return;

    console.log('البيانات:', { email: email.value });
    // لاحقاً: fetch إلى Flask
});

دعونا نشرح القرارات:
- استخدمنا دالتَي setError وclearError لتجنب التكرار.
- كل دالة تحقق تُرجع نص الخطأ أو ''.
- نجمع الأخطاء ولا نتوقف عند أولها، حتى يرى المستخدم
  كل ما يحتاج تصحيحه.
- عند الفشل نوقف.
- عند النجاح نطبع في Console (لاحقاً: fetch).

الآن التعبير النمطي:
/^[^\s@]+@[^\s@]+\.[^\s@]+$/

هذا يتحقق من صيغة بريد بسيطة:
- لا مسافات.
- @ واحدة تفصل الجزأين.
- نقطة في الجزء الثاني.

ملاحظة: هذا ليس تحققاً كاملاً. البريد الصحيح حقاً لا يُعرف
إلا بإرسال رسالة تحقق. لكن هذا يكفي لمنع الأخطاء الشائعة
في الواجهة، والخادم سيتحقق أكثر.

[75:00 – 85:00] رسائل خطأ مفيدة وقابلة للوصول
============================================================

رسالة الخطأ ليست تفصيلاً. هي أهم ما يراه المستخدم عند
التعثر. جودة الرسالة تحدد إن كان سيتصرف أم سيستسلم.

خصائص الرسالة الجيدة:
1. واضحة: تصف المشكلة بدقة.
2. قابلة للتنفيذ: تقول كيف تُصحّح.
3. قريبة من الحقل.
4. بالعربية: لا رسائل متصفح مبهمة.
5. تختفي عند التصحيح.

مقارنة سريعة:
- "خطأ!" → عديمة الفائدة.
- "Invalid input" → مبهمة.
- "الحقل مطلوب" → أي حقل؟ في أي قسم؟
- "البريد الإلكتروني مطلوب." → واضحة.
- "صيغة البريد غير صحيحة. مثال: name@example.com." → ممتازة.

الآن الوصولية. هذه نقطة تُنسى كثيراً.

نستخدم في HTML:
- small role="alert" للرسالة.
- aria-invalid="true" على الحقل عند الخطأ.
- aria-describedby يربط الحقل بالرسالة.

لماذا؟
لأن قارئ الشاشة يجب أن يعرف:
- أن هذا الحقل صار غير صالح.
- أن هناك رسالة تصف المشكلة.

role="alert" يجعل قارئ الشاشة يُعلن النص فور ظهوره.
aria-invalid يعطي حالة الحقل.
aria-describedby هو الرابط.

هذه الثلاثة معاً تنقل تجربة المستخدم البصري
إلى المستخدم غير المبصر.

ولا ننسَ CSS:
input.invalid { border-color: #ef4444; }
.error { color: #fca5a5; display: block; min-height: 1.2em; }

min-height ثابت لرسالة الخطأ مهم:
بهذا لا يقفز التخطيط عند ظهور/اختفاء الرسالة.

ولا تعتمد على اللون وحده. استخدم أيقونة أو نصاً أيضاً،
لأن بعض المستخدمين لا يميزون الألوان.

[110:00 – 120:00] أخطاء شائعة ونصائح
============================================================

دعونا نمرّ على الأخطاء:

أولاً: نسيان preventDefault.
النموذج يُرسل، الصفحة تُعيد التحميل، كل شيء يختفي.
القاعدة: أول سطر في معالج submit هو preventDefault.

ثانياً: null عند السكربت المبكر.
querySelector تعيد null لأن DOM لم يُبنَ بعد.
الحل: defer أو نهاية body، والتحقق قبل الاستخدام.

ثالثاً: innerHTML مع نص المستخدم.
يفتح ثغرة XSS. استخدم textContent للنصوص.

رابعاً: الاعتماد على onclick.
يستبدل المستمع السابق. استخدم addEventListener.

خامساً: إخفاء مؤشر التركيز.
outline: none على focus يدمر الوصولية.
إن أردت جمالاً، استبدله لا تحذفه.

سادساً: مقارنة القيم بـ ==.
مدخلات النماذج نصوص. استخدم تحويلاً صريحاً:
Number(value) === 0.

سابعاً: التحقق داخل كل input.
يُزعج المستخدم الذي لم يُكمل.
استخدم submit أو blur.

ثامناً: الاعتقاد أن تحقق الواجهة أمان.
ممكن تجاوزه. كرر التحقق في Flask.

نصائح:
- ضع كل مستمعاتك في نهاية الملف أو بعد DOMContentLoaded.
- احفظ مراجع العناصر في const، لا تبحث كل مرة.
- استخدم console.log أولاً، أزله قبل التسليم.
- اقرأ e.target لتعرف من أطلق الحدث.
- اختبر بلوحة المفاتيح، لا بالفأرة فقط.

نلخص المحاضرة:

- DOM تمثيل شجري للصفحة يبنيه المتصفح من HTML.
- document هو الجذر، وكل وسم يصبح عنصراً.
- الاختيار: getElementById، querySelector، querySelectorAll.
- التعديل: textContent للنصوص، innerHTML بحذر،
  classList للتفاعل، setAttribute للخصائص.
- الأحداث: addEventListener مع click، submit، input، blur.
- preventDefault ضروري لمنع الإرسال الافتراضي.
- التحقق من الواجهة يحسّن التجربة، لا يحل محل الخادم.
- رسائل خطأ جيدة: واضحة، عربية، مرتبطة بالحقل،
  مع role="alert" وaria-invalid.
- ضع السكربت في نهاية body أو defer.
